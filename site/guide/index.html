Reader help

User guide

Browse arXiv papers as a guest, understand optional account features, and control the data kept on your device.

Availability and installation

Pakperk Production v0.0 targets Android 7.0 / API 24 or newer and iOS 15 or newer. Install or update it only through an official App Store or Google Play listing published by the service operator. If no official listing is linked, Production v0.0 is not yet publicly available.

Accounts, To Read, and comments are independently controlled release capabilities. A build may offer guest reading without them; the app should not advertise a disabled capability.

Read papers

  1. Use Read for the paper feed and reader. Move vertically for the next or previous paper.
  2. Move horizontally, or use the labeled controls, between Abstract, Introduction + Assistant, and Connections. When Deep Reader is enabled, Skim, Read, and Inspect change the current paper's depth without adding horizontal pages.
  3. Use the arXiv action to inspect the original record. Pakperk does not replace the source paper and is not affiliated with arXiv.

The first committed move into Introduction can start preparation. In a strict release, Introduction, Chat, or Connections may be unavailable—even online—when a paper's license or prepared capabilities do not permit derived content. Cached metadata and the original arXiv link remain available.

Pakperk opens cached metadata before refreshing it. Offline, strict content policy may hide cached derived material that cannot be revalidated; this is a rights-protection boundary, not necessarily a loading failure.

Deep Reader, Passport, visual objects, assistant v2, annotations, research memory, and version comparison are staged, default-off capabilities. Generated fields and answers must link to exact source blocks. A missing or unsupported result is shown as unavailable or not found; the original source remains available.

Accounts and To Read

Use You for account features when they are enabled. Sign-in happens in the system browser. A public handle contains 3–30 lowercase ASCII letters, digits, or underscores and can be set only once.

Use the paper save control to add or remove an item from To Read. Changes synchronize when the network and a verified account are available. Remove offers Undo; offline and pending states remain visible. Saving a paper does not start preparation.

Comments and safety

Guests can read published discussion when comments are enabled. Posting requires a verified account, a handle, and acceptance of the current Terms and Community Guidelines. Comments are public plain text; drafts remain local until you send them.

Open You → My comments to revisit your posts. An Under review comment is visible only to you and authorized moderators until it is resolved.

  • Report comment privately reports one comment; it does not hide or block the author.
  • Report user privately reports an account-level pattern; it does not create a block.
  • Block user removes that author's comments from your view; it does not create a report.

Settings and data on this device

Open You → Settings for appearance, cache use, licenses, and local data controls.

  • Clear reading cache removes rebuildable feeds, generated reading views, cached discussions, and anonymous chat cache. It preserves your account, saves, drafts, pending synchronization, settings, and current reading position.
  • Clear all data signs out and removes local papers, saves, drafts, pending changes, settings, reading position, and the anonymous device identity. Data already synchronized to your account remains on the server.
  • Delete account is a separate server-side action that removes the provider identity, Pakperk profile, To Read data, comments, blocks, reports, and pending account-owned work. Clearing local data alone does not delete server data.

When private research features are enabled, annotations, note conflicts, evidence cards, checkpoints, memory items, cached versions, and pending research work are stored account-scoped in Drift. Those bodies are ordinary SQLite text, not application-layer encrypted. Local protection depends on the device passcode/access controls, OS app sandbox and file protection, and backup policy. Authentication refresh/session material remains separate in platform secure storage.

Account deletion and support

Use the in-app deletion control or the public deletion route. A recent sign-in is required. If deletion stalls, use the built-in support action; it includes a validated request identifier when available. Retain an operation ID only if the app or site shows one, and never send a password or token.

For safety, privacy, copyright, accessibility, or account help, read Support and safety or contact the operator. The Privacy Notice, Terms, and Community Guidelines contain the complete published rules.
