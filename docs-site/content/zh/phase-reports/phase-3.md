## 范围与保留的不变量

- 访客 Feed、论文、准备、处理、Introduction、匿名聊天、Connections、arXiv 链接和缓存阅读保持独立于账户可用性。
- `ACCOUNTS_ENABLED=false` 不注册任何 `/v1/me` 路由，也不执行 OIDC 发现。Library、评论、屏蔽、举报和删除路由保持不发布，无论其后续阶段的开关如何。
- 启用账户后的必需认证路由在发现、JWKS、令牌验证或账户存储不可用时会失败即拒绝。该失败不会让公开阅读服务变为未就绪。
- 认证绝不会改变准备边界：启动、会话恢复、JIT 即时预配、资料刷新、引导和退出登录都不能提交论文准备请求。
- 任何密码都不会进入 Pakperk。令牌和 OIDC 主体标识始终位于常规偏好设置、Drift/SQLite、日志、分析、崩溃报告和公开资料响应之外。

精确的设置、存储边界、资料形态、并发标头、错误类别和 CORS 技术契约记录在[账户认证与用户资料技术契约](../account-authentication.md)中。

## 后端身份边界

独立的 `auth` crate 提供：

- 有界、无重定向的 OIDC 发现和 JWKS 读取；
- 显式的非对称算法允许列表；
- 精确的签发方和受众检查，加上必需的 `exp`、`iss`、`aud` 和非空 `sub` 声明；
- 带有界时钟偏移的过期/not-before（生效时间下限）验证；
- 按 `kid` 查找签名密钥、合并并发的未知密钥刷新、刷新冷却、基于 TTL 的刷新，以及大小/密钥数边界；
- 脱敏的启动和验证失败，不保留任何令牌、声明、签发方、密钥 ID 或上游响应正文；以及
- 一个可克隆的认证运行时，它能在后台发现重试后原子地发布可用验证器，而无需重建公开路由器。

第 3 阶段的身份管理边界对破坏性操作有意不完整。`NoopIdentityAdmin` 绝不报告虚假成功，且经过验证的 Keycloak 适配器会报告 `Unwired`，直到 Phase 6 提供凭据加载、提供商调用、有界重试和删除幂等性。

## 本地账户与资料模型

迁移 `0004_accounts.sql` 引入本地 `users` 行，每个精确的 `(oidc_issuer, oidc_subject)` 身份对应一行。OIDC 签发方和主体标识是私有的。所有者投影包含服务器 UUID、可选的不可变用户名、可选显示名、状态、单调资料版本、条款接受和时间戳。

JIT 即时预配是事务性的，并且在并发首次请求下是安全的。它不复制提供商电子邮件或资料字段，也绝不重新激活被封禁/删除状态的账户。`last_seen_at` 以有界的节奏更新，而不是在每个请求时写入。

用户名是规范的 ASCII 小写值，只包含字母、数字和下划线，长度为 3–30 个字符，保留/系统名称以及 URL/电子邮件形状会被拒绝。数据库强制执行防御性的不区分大小写唯一性。显示名是可选的，经 NFKC 规范化、空白折叠，限制在 80 个 Unicode 标量值内，并拒绝控制/方向性字符。

资料写入使用强 `"profile-N"` 验证器和比较并交换版本控制。省略与显式 null 的显示名保持不同；用户名只能设置一次且不能清除；已接受的条款必须匹配配置的当前版本。只有拥有用户名和当前条款接受的活跃账户，其资料才算完整。

## 共享限流基础

迁移 `0005_shared_rate_limits.sql` 为每个 `(bucket, scope_key)` 新增一行有界的固定窗口记录。数据库语句执行时间和原子的 `INSERT ... ON CONFLICT ... DO UPDATE` 使强制执行对所有 API 副本通用。第一个使用方是 `profile_update`，仅由已验证的 Pakperk 用户 UUID 作键。有界的跳过锁定清理操作会移除过期窗口。后续阶段会添加论文库、评论、举报、删除以及最终的准备/聊天迁移，而无需另一个网络服务。

## 已认证资料 API

启用账户后，服务器会发布：

```text
GET   /v1/me
PATCH /v1/me
```

两者都要求 OpenAPI `oidcBearer` 安全方案，对已验证身份进行 JIT 映射，返回 `Cache-Control: private, no-store`，并返回与资料版本匹配的强 ETag。`PATCH` 要求精确的 `If-Match`，拒绝未知或空输入，并在成功时递增资料版本。

稳定的错误封装覆盖认证、账户状态、验证、用户名冲突、前置条件冲突、共享限流以及临时的认证/存储不可用。质询和重试时机通过标头传递，而不是响应正文中的令牌/提供商详情。已检入的 [OpenAPI 产物](../openapi-v1.json)必须从代码优先的技术契约重新生成并通过兼容性检查，然后本阶段才能被接受。

## 移动端会话与资料行为

移动端认证层与 Dio、Riverpod UI 和账户 API 分离：

- AppAuth 会打开系统浏览器执行 Authorization Code + PKCE 和提供商注销。
- 访问令牌只存在于内存中。平台安全存储持有刷新令牌、可选的 ID 令牌注销提示、签发方/客户端绑定，以及带严格版本化编解码器的可选非密钥本地账户 UUID。
- 并发调用方共享一个主动的或质询驱动的刷新。401 可以重放一次；写重放还额外要求有界的 `If-Match` 或幂等标头。
- Bearer 凭据只附加到精确配置的 Pakperk API 源。公开请求绝不等待认证，外部源也绝不会收到令牌。
- 纪元防护会阻止迟到的登录、刷新、账户获取、引导或清理工作复活过期的会话。
- `invalid_grant` 会产生访客状态；普通的提供商/网络错误会保留离线/认证未知会话。
- 退出登录会清除安全凭据和归账户所有的 Drift 行，同时保留公开 Feed/论文缓存和阅读器恢复状态。

账户客户端严格解析所有者封装和 ETag，区分省略/null/有值补丁，并使用一个当前账户控制器。You 分支在功能关闭时保持其访客状态，在启用时启动真实的系统认证，JIT 加载 `/v1/me`，为不完整账户请求用户名/当前条款引导，显示已认证的所有者状态，并支持退出登录。待处理的已认证操作最多持有一个经过验证的意图，供后续的收藏/评论阶段使用。

## 原生与开发提供商集成

- Android 声明精确的 AppAuth 重定向方案，使用 API level 23 或更高版本以实现安全存储，禁用备份，并提供备份/数据提取排除项。
- iOS 注册相同的回调方案，使用设备绑定的 Keychain 数据保护类别，并禁用共享的磁盘 URL 缓存，这样包含令牌材料的 AppAuth 响应 URL 就不会被持久化。
- 可选的 Compose `accounts` profile 通过摘要固定 Keycloak 26.7.0、PostgreSQL 16.14 和 Mailpit 1.30.6。其导入的开发 Realm 拥有原生公共客户端、精确的回调/注销 URI、PKCE S256、API 受众、自助注册、电子邮件验证/恢复、暴力破解防护和轮换的刷新令牌。

## 退出标准台账

- **OIDC 离线/不可用时访客阅读仍可工作：**由真实的提供商中断路由检查以及必需/可选主体测试验收。
- **测试用户可以注册、验证并登录：**由真实的 Keycloak/Mailpit/PKCE 冒烟流程验收。
- **令牌不出现在常规存储/日志中：**由严格的 codec/schema 安全检查加上密钥脱敏测试验收。
- **过期的访问令牌只刷新一次：**由合并并发和单次重放传输测试以及真实的刷新令牌轮换验收。
- **无效刷新返回访客状态而不清除公开缓存：**由 `invalid_grant`、持久失效、重启和限定范围清理测试验收。
- **用户名唯一性和资料版本控制正常工作：**由真实 PostgreSQL 和 HTTP ETag/前置条件场景验收。
- **账户功能可以连贯地禁用：**由后端路由缺席、无发现、移动端功能开关和访客壳层测试验收。

## 已知风险与后续阶段边界

- 模拟器构建和源代码/资源检查不能替代在签名的真机发布候选版本上进行的最终 Keychain/Keystore、回调、备份/恢复和注销检查。
- 在长时间提供商中断期间，OIDC 启动重试必须保持有界且不含内容；必需认证的失败不得改变公开就绪状态。
- 类生产的身份部署需要自己的 HTTPS 签发方、Realm、原生客户端、密钥管理、备份和可用性计划。开发 Realm 不是生产配置。
- Keycloak 管理会话撤销和身份删除在 Phase 6 之前有意保持未接线；`/v1/me` 删除必须在第 3 阶段保持缺席。
- Library 操作、公开评论、UGC 控件、内容审核和删除不会因账户资料界面而变为已完成，并在阶段 4–6 中保持独立门禁。
