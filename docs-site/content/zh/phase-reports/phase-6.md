- **已实现、仓库可测试：** 删除状态机/监控界面；参考提供商删除测试框架；恢复重新应用机制；独立的紧急关闭开关；迁移与回滚流程；遥测验证/脱敏拓扑；不可变的告警/证据技术契约；有界的预发布负载测试框架；安全/源代码/原生 SBOM 自动化；确切 SHA 镜像发布与已签名候选版本工作流；一次性评论/内容审核工作流与经脱敏的证据技术契约；来源绑定的公共边缘工作流与经脱敏的证据技术契约；确切 main 的受保护认证/重放/共享限制/六开关工作流与封闭证据技术契约；规范的迁移、遥测与移动端性能运营清单及共同来源捆绑包；披露/操作手册产物。
- **尚未获得外部证明：** 针对目标提供商（使用其真实密钥管理器、台账、告警路由与备份清单）的受保护预发布删除；一次真实的备份/PITR 恢复与删除重放；实时的迁移/回滚演练；实时的 OTLP 保留期、适配器、接收器与金丝雀寻呼；一次实际的受保护预发布负载结果；针对目标操作人员/适配器/告警/人员配备矩阵的完整受保护预发布内容审核就绪状态；确切候选版本的受保护签发方轮换/移除、写入重放、跨副本配额/重置、六开关演练、清理与所有者批准；规范的受保护迁移、实时遥测/保留期/告警以及已签名移动端性能/崩溃清单及其对账后的运营捆绑包；针对确切暗部署候选版本的一次成功的受保护公共边缘运行；当前的公告/容器扫描；受保护的镜像发布/摘要晋升与生产移动端签名；受保护的生产商店分阶段发布执行与商店审计对账；已测量的启动/缓存/崩溃目标；物理设备 QA；法务/内容评审；审核者账户/备注；当前的商店表单；TestFlight/封闭 Play 上传与评审状态。

因此，第 6 阶段是一个暗发布仓库候选版本，而不是一项可以启用生产功能开关的声明。每一个外部项目，都需要一位负责人、一个时间戳、一个环境/构建版本、一个不可变的证据存放位置，以及一次批准。

## 已知风险与运维人员义务

- Collector 的 filelog 偏移量与导出器重试队列，使用各自独立的、有界的、限定于 Pod 范围的 `emptyDir` 存储。同一个 Pod 内的容器重启会保留两者，但 Pod 的替换、重新调度或节点丢失，可能会重放有界保留的文件。汇点必须能够容忍/去重重放，且运维人员必须测试节点覆盖率、轮转与队列饱和情况。
- Ingress 代理 CIDR 必须与 API 实际观测到的来源地址一致，而控制器只信任来自平台负载均衡器转发的地址。禁止使用面向整个互联网的信任范围。
- 最终的删除台账文件比可恢复备份存活更久，且需要历史签名/解密密钥。清理操作绝不会删除最终记录；最终清除是单次操作、经证据核验，且由运维人员控制。
- Android 上传密钥证据并不是已安装的 Play 身份。关联文件使用受保护的 Play App Signing 证书指纹。
- 商店历史记录、签名密钥、基础设施保留期、联系方式，以及法务/内容审核人员配备，都是有意保持在外部的，无法从本仓库推断得出。
- 一份分阶段发布结果回执，能够证明哪一次有界的 API 尝试成功、失败或未运行，包括依赖被跳过与部分成功的情形；但它无法证明某个商店已批准或已完全传播某次发布。商店端的历史记录与确切候选版本的观测窗口仍是必需的。完成前的暂停是终态的，且会使用更高版本的前向修复构建；仅 Android 还具备发布操作手册中所述的、受保护的完成后回退暂停机制。
- 公共边缘证据观测的是 site 声明来源标记与预期的公共响应技术契约。平台负责人仍必须将实际的 Pod 镜像 ID 与不可变的发布绑定 ConfigMap，与受保护的晋升交接文件进行比对；所请求的候选版本摘要并未被边缘观测到。
