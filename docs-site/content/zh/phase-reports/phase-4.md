# Production v0.0 第 4 阶段报告

**阶段：** To Read 论文库
**状态：** 已完成 — 已接受
**实施快照：** 2026-07-31
**起始提交：** `728ae3d`

这是已接受的第 4 阶段记录。它收口第一个归账户所有的阅读器功能：一个带乐观离线写操作、持久重试、基于修订的跨设备收敛和缓存元数据的同步 `to_read` 集合。它不声称公开评论、账户删除或适用于整个发布的 Production v0.0 完成定义已经完成。

权威的传输格式、分页、冲突、保留和准备行为记录在 [To Read 论文库同步技术契约](../library-sync.md)中。

## 保留的不变量

- 访客 Feed、论文阅读、惰性准备、处理、Introduction、聊天、Connections 和 arXiv 链接保持独立于账户和论文库。
- `LIBRARY_ENABLED=false` 不发布任何论文库路由或移动端控件。`LIBRARY_WRITES_ENABLED=false` 保留列表/变更读取，同时 PUT/DELETE 以 503 `FEATURE_DISABLED` 失败。
- 任何活跃账户均可收藏，无需用户名、当前条款或论文准备。
- Library 列表、变更、收藏和移除路径不执行任何 arXiv、PDF、GROBID、模型或准备队列工作。
- 不存在可观察到的全局收藏计数或跨账户水位线。

## 后端论文库模型与 API

迁移 `0006_library.sql` 和 `0007_per_user_library_revisions.sql` 新增支持墓碑的论文库行、持久操作台账、按用户划分的同步元数据、索引和共享的写操作限流。修订在单个账户内以事务方式分配。向前修正会把任何初始全局时钟数据安全地重定基准到重置屏障之上，因此修正前的客户端必须执行一次明确无误的完整刷新。

启用功能门禁的 API 恰好发布以下路由：

```text
GET    /v1/me/library
GET    /v1/me/library/changes
PUT    /v1/me/library/{paper_id}
DELETE /v1/me/library/{paper_id}
```

列表分页使用账户修订隔离线，并要求最后执行一次变更遍历。变更按升序返回，包含移除墓碑，且绝不会因其他账户的活动而推进。墓碑保留 90 天；有界清理会在删除前推进按用户划分的重置下限，较旧的客户端会收到 410 `LIBRARY_SYNC_RESET_REQUIRED`。

两个写操作方向都使用一个规范客户端 UUID。完全一致的重放返回规范行；将同一 UUID 用于其他论文或其他意图会返回 409 `LIBRARY_OPERATION_CONFLICT`。操作记录、规范写操作、修订分配和限流行为均按事务顺序执行。清理会先按确定性的 UUID 顺序锁定按用户划分的元数据，再处理子行，从而避免其写操作竞态。

所有私有结果的响应均为 `Cache-Control: private, no-store`。DTO 会拒绝未知或格式错误的状态、游标、limit、修订、操作、标头、正文和论文值。严格全文策略会在不改变论文节点收藏关系的前提下遮蔽摘要能力。已检入代码仓库的 OpenAPI 产物包含全部四个路由、Bearer 安全方案、请求/响应 schema、标头、错误、示例和功能门禁描述。

## 移动端离线与身份行为

Drift schema 版本 4 存储账户范围的论文库行、规范回滚状态、同步检查点和持久化待同步队列（outbox）。本地写操作和操作 ID 在同一事务中提交。可见的已收藏状态流驱动每个论文阶段和 To Read 副本；收藏立即生效，移除会作为新操作提供撤销，待处理/永久的同步状态仍可操作。

同步引擎会串行化每篇论文的工作，在重启后回收被中断的发送，保留已发送的操作 ID，在完整替换后叠加待处理意图，以事务方式应用变更，并使用指数退避、正数抖动和服务器完整的 `Retry-After` 下限重试可重试的失败。已收藏论文的元数据会通过普通的公开缓存淘汰保持固定，并在移除或限定范围的账户清理时释放。

离线显示和远程授权使用各自独立的作用域。已持久化的账户 ID 可以在凭据刷新期间显示其缓存行，但排空和刷新要求一个活跃的 `/v1/me` 资料，并针对确切且当前的认证纪元和账户 ID 完成验证。如果存储的账户 A 解析到账户 B，则会在 B 绑定前清除 A 的行和待同步队列（outbox）；绝不能使用 B 的 Bearer 令牌发送 A 的操作，也绝不能把 B 的响应提交到 A 之下。

阅读器会在阶段翻页器上方提供一个无障碍的“Save to To Read”控件，因此 Abstract、Introduction 和 Connections 共享同一状态。访客收藏会通过 PKCE 保留一个待处理动作；收藏并不要求完成资料引导。失败会保留显式的重试路径，而系统返回会清除待处理意图。You 分支提供离线优先的 To Read 列表、Read 导航、刷新、移除/撤销、空状态、离线、待处理和错误状态。Section 2.4 宽屏适配增强（于 2026-08-03 新增）保留最新收藏作为默认排序，同时新增本地最新/最旧/标题排序、标题/作者/arXiv/类别搜索和精确的类别筛选。这些控件只对已加载的账户投影进行操作，因此缓存和离线列表既不会发出新请求，也不会丢失待处理状态。

## 退出标准台账

- **收藏/取消收藏立即更新：**由共享的 Drift 投影以及阅读器/列表组件测试验收。
- **两台设备收敛：**由确定性跨设备测试和真实 PKCE/API 流程验收。
- **离线收藏在重启后存活并稍后同步：**由持久化待同步队列（outbox）恢复和网络恢复测试验收。
- **重复交付只产生一个规范状态：**由服务、真实 PostgreSQL、HTTP 和真实提供商重放场景验收。
- **墓碑与旧客户端重置安全收敛：**由真实数据库保留/重置测试和移动端完整替换叠加测试验收。
- **已收藏元数据在普通淘汰后存活：**由 Drift 淘汰、移除和清理测试验收。
- **写紧急关闭开关保留阅读能力：**由独立的真实 API 和路由注册测试验收。
- **Library 不触发任何准备：**从结构上、由服务/API 测试以及未改变的真实作业/阶段计数验收。
- **已收藏论文排序/筛选：**聚焦组件测试覆盖确定性的最新/最旧/标题排序、作者搜索、类别筛选、无结果恢复、真实结果语义、48 像素控件、200% 文本回流，以及 `ActiveLibraryScope` 对查询、类别、排序和滚动状态的隔离。

## 已知风险与后续阶段边界

- 模拟器构建和源代码/资源检查不能替代最终签名的真机数据库、安全存储、离线/重启、无障碍和回调检查。
- 移动端 v0.0 刷新守卫会把超过 1,000 页视为不一致的快照；精确的 100,000 行列表上限记录在同步契约中，并有意高于初始产品规模。
- Phase 6 的账户删除必须使其级联锁定顺序与论文库墓碑清理保持一致，并包含一个确定性的真实并发回归。
- 公开评论、UGC 策略控件、内容审核和账户删除仍保持独立门禁，不会因本阶段而变为已完成。
