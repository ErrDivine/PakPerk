# Production v0.0 第 2 阶段报告

**阶段：** Drift 缓存与 Feed 预取
**状态：** 已完成
**实施快照：** 2026-07-31
**起始提交：** `d0083f9`

本报告记录已接受的第 2 阶段实施。它不声称账户、同步的论文库操作、评论、内容审核或 Production v0.0 发布已完成。

## 范围与保留的不变量

- 批量公开内容移到 Drift/SQLite `LocalStore` 之后；匿名身份和导航恢复仍保持为小的 SharedPreferences 值。
- 启动保持缓存优先。有效且已迁移或已存在的设备 Feed 可以在没有网络访问的情况下产出首个可读帧，内置语料库仅作为韧性回退保留。
- 预取只有 Feed 专用的远程接口。它不能调用论文准备、处理、Introduction、聊天、Connections、arXiv、PDF 或模型提供商。
- 在公开内容进入或离开设备缓存之前，严格全文遮蔽都会生效。生产持久化不会削弱服务器策略。
- 论文新鲜度先按 arXiv 版本、再按源更新时间保持单调。派生记录限定在当前 arXiv 版本和处理代次范围内，因此迟到的网络响应无法恢复过期能力。
- Drift schema 中不存在凭据或授权字段。Phase 2 不新增登录行为，也不存储访问或刷新令牌。

## 关系型设备缓存

稳定的生产数据库是 `pakperk_content.sqlite`。已接受的第 2 阶段快照引入了 schema 版本 3；在论文库和评论阶段扩展了同一条显式迁移链之后，当前生产代码树是 schema 版本 6。外键和 WAL 保持启用。其数据表覆盖缓存的论文、Feed 查询和有序成员关系、处理、Introduction、Connections、评论页面、匿名聊天、论文库投影、草稿、待同步队列（outbox）和缓存元数据。

面向账户的数据表只是基础。在各自完整的后续阶段落地之前，账户、论文库和评论保持禁用。Library 墓碑有意独立于公开论文行的生命周期，而活跃的论文库行会投影到 `cached_papers.pinned_by_library` 以获得淘汰保护。

Feed 持久化按类别和页面上限做到精确。论文行、Feed 成员位置、游标、刷新时间和首页验证器以事务方式提交。游标页面会追加成员关系而不擦除该验证器。缺失、损坏或有缺口的成员关系会使验证器失效，而不是让虚假的 `304` 为不完整的页面背书。

论文元数据会拒绝更旧的 arXiv 版本、同一版本内更旧的更新，以及把现有稳定论文 ID 绑定到另一项 arXiv 作品的尝试。真正的元数据前移会以原子方式清除处理、Introduction、Connections 和匿名聊天行。派生写入会捕获预期的论文版本、比较其处理代次，并在任一边界前移后拒绝迟到的响应。

匿名聊天以 `(session_id, reader_key)` 为键，携带论文版本和处理代次上下文，并且会过期。匿名身份轮换会在提交新身份之前清除缓存的聊天和可恢复的聊天标识符，防止旧会话内容被新会话读取。

## 从 SharedPreferences 迁移

一次性导入器会识别以前的 Feed、论文、处理、Introduction、Connections 和聊天键。它使用现有的模型解析器，在一个事务中导入已接受的行，验证结果，写入 Drift 迁移标记，然后才移除旧版批量键。论文元数据可以独立恢复。派生行要求精确的单独缓存 arXiv 版本加上显式序列化的正数代次，子行要求在该代次成功导入的处理行。聊天还要求与精确的 Feed/恢复路由阅读器键以及导入器构造时采样的匿名会话匹配的显式 session/paper/arXiv 字段。并发创建或更晚的会话不能为较旧的聊天提供溯源信息。在提交标记之前，导入器会复查完整且不可变的批量偏好快照以及任何已导入聊天的会话；只有当键的值仍与该快照匹配时，清理才会移除该键。因此，源变更或会话轮换会无数据丢失地回滚，冻结的无范围 v1 派生/聊天 blob 会被计为未绑定并丢弃，只有完全绑定的过渡记录才能迁移。类型错误、损坏和未绑定的值会被处理，而不记录其内容。如果解析或事务验证失败，启动会继续，源偏好设置仍保留以供将来重试。

Drift schema 具有由完整冻结的历史测试夹具构建的就地迁移测试。版本 2 新增 Feed 条目计数、条件 Feed 验证器和匿名聊天持久化。版本 3 新增处理代次上下文。早于该上下文且可重建的派生行会被删除，而不是被不准确地重新标记。版本 4–6 扩展了同步的论文库和绑定账户的评论状态，并移除了休眠的回复列。严格策略导入会保留遮蔽后的元数据，但丢弃所有派生的全文和聊天记录。

## 预测性 Feed 协调器

`FeedPrefetchCoordinator` 由已提交的垂直页面变更驱动，并把所有生产调优值保存在 `FeedPrefetchConfig` 中：

| 设置 | 默认值 |
|---|---:|
| 远程页面大小 | 30 |
| 加载触发条件 | 剩余 10 篇论文 |
| 可读窗口 | 向后 2 篇 / 向前 6 篇 |
| 持久目标 | 向前 60 篇 |
| 元数据行上限 | 500 篇论文 |
| 真实/物理数据库目标 | 64 MiB（二进制兆字节） |
| 元数据 TTL | 7 天 |
| 首个评论页 TTL | 5 分钟 |
| 淘汰延迟 | 500 毫秒 |

协调器会为可读窗口修复元数据、记录当前论文访问，并且只在剩余尾部达到触发条件时启动游标抓取。每个查询只有一个进行中的请求。页面会按稳定的论文 ID 去重而不回退 arXiv 版本，重复较多的页面会持续抓取，直到持久目标实际存在或分页结束。

类别变更和权威的同查询快照替换会取消或逻辑废弃旧工作。循环游标和无进展页面会终止。网络故障会让现有卡片保持可读，并安排有界的带抖动指数退避；已提交的页面前移或连接恢复会重置重试状态。预取的游标页面只有在其查询和快照代次仍是当前值时才会更新控制器。

## 有界淘汰与遥测

低优先级淘汰会先移除过期的评论页面、过期的非活跃 Feed 成员关系、未固定的 LRU/TTL 论文行，然后在字节压力仍存在时移除已过期且最旧的无保护派生代次簇。当前论文、即时阅读器窗口、已恢复的路由和聊天、活跃的论文库固定项、草稿和待处理的待同步队列（outbox）所有权都受到保护。行数和真实 SQLite 页面字节会在普通维护期间强制执行。物理占用包括数据库、WAL 和共享内存文件；检查点和 `VACUUM` 以合并并发方式运行，并且只在应用进入非交互生命周期状态后运行。

预取遥测对请求、成功、失败、去重、下一篇论文命中/未命中、空白卡片、缓存行/字节和可读时间事件采用闭合的数值形态。它没有字符串属性，防止标题、摘要、作者、类别、评论、游标和原始标识符被附加。

## 条件式 Feed 传输

Rust Feed 端点会返回一个不透明的弱 ETag，它以 SHA-256 对完整查询表示、每个公开论文字段、下一页存在性以及活跃游标加密密钥的非密钥纪元推导而成。随机游标密文被排除，因此重复响应保持语义稳定；而密钥晋升会改变纪元，并在旧密钥退役前强制返回携带新游标的 `200`。该标签不直接暴露数据库 ID、时间戳或密钥材料。成功且未变化的响应包括：

```text
ETag: W/"pp-feed-v2-..."
Cache-Control: public, max-age=60, stale-while-revalidate=300
```

`If-None-Match` 支持弱比较、通配符、列表、重复标头字段和带引号的不透明值。格式错误或超限的输入会回退到无条件响应。匹配会返回带相同缓存标头的空 `304`。CORS 允许 `If-None-Match` 并暴露 `ETag`，OpenAPI 则记录该请求标头以及 `200` 和无正文 `304` 两种响应。

移动客户端只为匹配的首页查询发送已存储的验证器。`304` 会重新发布精确的缓存页面并更新其刷新时间；省略 `ETag` 的响应会保留该请求使用的验证器。没有可读页面的孤立验证器会用一次无条件请求修复。网络故障会继续服务精确的缓存查询，包括有意为空的类别结果，而不是泄漏全 Feed 页面。

## 退出标准映射

- **迁移后缓存 Feed 可离线打开：**由启动流程在选择 Drift 或内置内容之前等待非阻塞导入器实现；由迁移/启动测试覆盖。
- **普通顺序测试达到 >=95% 的下一卡片命中：**确定性的 100 篇论文场景断言该比率，并只把它的第一次转换记录为未命中。
- **快速滑动期间无重复请求：**每查询合并并发测试断言一次远程调用和一个去重事件。
- **最大缓存边界：**独立的行/真实字节测试和基于文件的物理分配测试覆盖淘汰和生命周期安全的压缩。
- **论文库界面之前存在已收藏论文固定项：**schema 和账户缓存 DAO 会把活跃的论文库行投影到论文固定项，同时在公开元数据淘汰后保留墓碑。
- **准备计数不因预取而改变：**预取适配器只暴露 `getFeed`；其边界测试断言零次 prepare、处理、Introduction、聊天、Connections、论文修复和 arXiv 查找调用。

这些映射为每个第 2 阶段退出标准确定了实施和测试。第 2 阶段已接受；后续生产阶段仍是独立的门禁。
