# 生产 v0.0 阶段 0 报告

**阶段:** 基线冻结、ADR 和无行为重构  
**状态:** 完成  
**完成日期:** 2026-07-31  
**基线:** `8dd3bc6aab1ab0fe058c5ace8ab1107813cfb441`  
(`production-v0.0-baseline` 注释标签)

本报告仅记录阶段 0 的证据。它不声称后续生产功能或生产 v0.0 的完成标准是完整的。

## 运行的检查

在阶段 0 之前，现有的 Rust 格式化、Clippy、工作区测试、Flutter 格式化、Flutter 分析和 58 个 Flutter 测试通过。第一次包装调用无法在工作区沙箱下更新 Flutter SDK 缓存；相同的 Flutter 命令在 SDK 缓存权限下重新运行并通过。

阶段 0 之后，以下集成命令通过，没有跳过任何产品步骤：

```bash
./scripts/check.sh
```

该运行包括：

- Rust 格式化和工作区 Clippy 带有 `-D warnings`；
- 所有 Rust 工作区单元测试、集成测试和文档测试；
- 确定性 OpenAPI 生成、检查的工件字节比较和四个兼容性检查器测试；
- Flutter 依赖解析、格式化、分析和 69 个测试；
- JSON 验证和 shell 语法检查。

显式要求 `TEST_DATABASE_URL` 的 opt-in 迁移测试在没有该变量的运行中仍被其现有 guard 忽略。其他 PostgreSQL 测试二进制文件成功完成，但通过其文档的 `TEST_DATABASE_URL` guard 提前返回，因此此本地运行不是数据库断言的证据。CI 提供 PostgreSQL 并对其进行测试；本地 Docker 守护进程在额外的服务支持运行中不可用。

## 添加的迁移

无。阶段 0 故意不添加账户、库、评论、审核或速率限制表。现有迁移保持不变。

## API 变化

- 将原来的 API 单体拆分为应用程序组装、验证配置、稳定错误、HTTP DTO、请求-ID/超时/速率限制中间件，以及健康/文章/论文/聊天/支持路由模块。
- 添加了类型化的 `development`、`staging` 和 `production` 环境。
- 添加了独立的账户、库和评论标志，带有依赖验证。这些标志保留在 `AppState` 中，但阶段 0 不注册任何不完整的功能路由。
- 添加了部署环境的 CORS 验证。测试和生产环境要求显式的 HTTPS 原点，不带通配符、凭证、路径、查询或片段。
- 生产环境拒绝运行时迁移、非严格全文策略和确定性模型提供者。
- 为所有十个现有公开路由添加了代码优先的 `utoipa` 文档，包括成功/错误正文和稳定的 wire 枚举。
- 在开发/测试环境中添加了 `/openapi.json`。
- 添加了确定性生成和一个检查的 [`openapi-v1.json`](../openapi-v1.json) 工件。CI 拒绝生成漂移和移除的路由、方法、响应代码、属性、组件模式和缩小的枚举值。模式-枚举测试将文档中的值绑定到实际的领域序列化。

现有的论文路由、响应序列化、准备意图、全文遮蔽、聊天所有权和速率限制行为保持不变。现有的 PostgreSQL API 集成测试仅更改以提供新要求的环境/功能配置字段。

## 数据库变化

- 将 3,385 行的仓库模块替换为稳定的公共外观，并专注于论文、聊天和私有行/编码模块。
- 保留了所有公共仓库方法和 SQL 字符串。拆分通过所有 325 个原始 Rust 字符串/原始字符串字面量和 DB 单元和 PostgreSQL 行为套件进行验证。
- 没有添加任何推测的账户仓库或模式。

## 移动变化

- 添加了类型化的构建环境和独立的账户、库、评论和打开动作标志。开发默认值保留当前的访客演示，所有生产标志禁用。
- 通过验证的构建配置集中了 API 基础 URL 和全文策略。
- 生产环境要求 HTTPS 和严格的全文策略；账户拥有的标志要求账户；评论要求非占位符支持 URL。
- 账户启用的构建要求签发者、客户端 ID、应用拥有的回调和退出后回调值。不安全的重定向方案、类似生产环境的通用链接、占位符和带有查询的回调被拒绝。
- 作为移动构建值提供的客户端密钥和提供者 API 密钥在验证失败时不会被静默捆绑。
- 添加了十一项聚焦的构建配置测试，同时所有现有的读者、恢复、手势、韧性、内容策略和聊天测试保持绿色。

## 文档和运营变化

- 添加了生产 v0.0 文档入口点和 ADRs 0001–0005。
- 更新了架构和内容策略文档，以区分实现的演示与计划的生产目标。
- 更新了 `.env.example` 和 `README.md`，以包含阶段 0 的功能/配置边界和合同命令。
- 添加了一个专用的 CI `contract` 作业，具有完整的历史记录用于基础工件兼容性比较。

## 退出标准证据

- **演示流程未变:** 所有先前的 Rust 和 Flutter 测试通过；没有账户 UI 或数据库表存在；功能默认值被禁用。
- **API 固定装置未变:** 现有的运行时断言和 wire 序列化器保持不变；新的工件文档而非替换其形状。
- **发布检查:** `./scripts/check.sh` 退出成功。
- **OpenAPI 覆盖:** 检查的文档包含恰好十个现有的健康/论文路由，且路由覆盖测试在未文档化的漂移上失败。
- **无公开账户:** 没有 `/v1/me`、库、评论或阻止路由被注册，无论阶段 0 标志值如何。

## 已知的风险带入后续阶段

- 阶段 1–6 的产品行为在此报告中故意未实现。
- 运行时功能清单必须在每个完整的服务器安全堆栈旁边扩展；单独的标志不是授权。
- OpenAPI 响应模式经过编译和回归检查，但未来的账户 DTO 必须继续相同的检查工件纪律。
- 设备级导航和启动动作接受测试属于阶段 1，因为阶段 0 不进行任何导航或视觉更改。
- 生产环境的 PostgreSQL 断言需要在 CI 或后续的本地运行中确认，使用 `TEST_DATABASE_URL`；此阶段的集成本地检查测试了它们的构建和守卫，而不是数据库主体。
- 本地基线标签必须在项目推送时与仓库引用一起发布；在此阶段没有进行远程更改。
