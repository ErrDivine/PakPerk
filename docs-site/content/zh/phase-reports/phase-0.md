**阶段：**基线冻结、ADR 与不改变行为的重构
**状态：**已完成

**基线：**`8dd3bc6aab1ab0fe058c5ace8ab1107813cfb441`

本报告仅记录阶段 0 的证据。本报告不表示后续生产功能已实现，也不表示已满足 Production v0.0 的完成标准。

## 已执行的检查

在阶段 0 开始前，现有的 Rust 格式检查、Clippy、工作区测试、Flutter 格式检查、Flutter 静态分析和 58 项 Flutter 测试均已通过。首次通过包装脚本执行时，由于工作区沙箱限制，无法更新 Flutter SDK 缓存；授予 SDK 缓存所需权限后，重新执行相同的 Flutter 命令并通过。

阶段 0 完成后，以下集成命令执行成功，且未跳过任何产品检查步骤：

```bash
./scripts/check.sh
```

此次执行包括：

- Rust 格式检查，以及带 `-D warnings` 的工作区 Clippy 检查；
- 所有 Rust 工作区单元测试、集成测试和文档测试；
- 确定性 OpenAPI 生成、受检构建产物的逐字节比较，以及四项兼容性检查器测试；
- Flutter 依赖解析、格式化、分析和 69 个测试；
- JSON 验证和 shell 语法检查。

需要显式设置 `TEST_DATABASE_URL` 才会运行的可选迁移测试，在未设置该变量时仍会由现有守卫条件跳过。其他 PostgreSQL 测试可执行文件均成功结束，但会按已记录的 `TEST_DATABASE_URL` 守卫条件提前返回；因此，此次本地执行不能作为实际数据库断言已运行的证据。CI 会提供 PostgreSQL 并执行这些测试；当时本地 Docker 守护进程不可用，因而无法额外执行依赖实际服务的测试。

## 新增迁移

无。阶段 0 刻意不新增账户、文献库、评论、内容审核或限流相关的数据表。现有迁移保持不变。

## API 变化

- 将原有的 API 单体拆分为应用组装、经验证的配置、稳定错误、HTTP DTO、请求 ID/超时/限流中间件，以及健康检查/信息流/论文/聊天/支持路由模块。
- 添加了类型化的 `development`、`staging` 和 `production` 环境。
- 新增带依赖校验的独立账户、文献库和评论功能开关。这些开关保留在 `AppState` 中，但阶段 0 不会注册任何尚未完整实现的功能路由。
- 新增已部署环境的 CORS 校验。预发布和生产环境必须显式配置 HTTPS 来源，且不允许通配符、凭据、路径、查询字符串或 URL 片段。
- 生产环境拒绝运行时迁移、非严格的全文策略，以及确定性模型提供方。
- 为现有的十个公开路由新增代码优先的 `utoipa` 文档，包括成功/错误响应体和稳定的线上传输枚举。
- 仅在开发/预发布环境中新增 `/openapi.json`。
- 新增确定性生成流程和一份受检的 [`openapi-v1.json`](../openapi-v1.json) 构建产物。CI 会拒绝生成结果漂移，也会拒绝删除路由、方法、响应码、属性、组件 schema 或收窄枚举值范围。schema 枚举测试会将文档值与实际的领域序列化结果绑定。

现有的论文路由、响应序列化、预处理意图、全文脱敏、聊天所有权和限流行为均保持不变。现有 PostgreSQL API 集成测试的唯一变更，是补充新增的必填环境/功能配置字段。

## 数据库变化

- 将原来 3,385 行的仓储模块拆分为稳定的公开门面，以及职责单一的论文、聊天和私有行/编解码模块。
- 保留所有公开仓储方法和 SQL 字符串。通过比对原有的 325 个 Rust 字符串/原始字符串字面量，并执行数据库单元测试和 PostgreSQL 行为测试套件，验证了此次拆分。
- 未增加任何超前设计的账户仓储或 schema。

## 移动变化

- 新增类型化的构建环境，以及相互独立的账户、文献库、评论和启动动效开关。开发环境默认值保留当前的访客演示体验，所有生产功能开关均为关闭状态。
- 通过验证的构建配置集中了 API 基础 URL 和全文策略。
- 生产环境必须使用 HTTPS 和严格全文策略；账户所有的功能开关依赖账户功能；评论功能必须配置非占位符的支持 URL。
- 启用账户功能的构建必须提供发行者、客户端 ID、应用自有回调和退出后回调值。不安全的重定向 scheme、在类生产环境中使用的回环 Universal Link、占位符和带查询字符串的回调均会被拒绝。
- 如果将客户端密钥或提供方 API 密钥作为移动端构建值传入，配置校验会直接失败，而不是将它们静默打包进应用。
- 新增十一项针对构建配置的聚焦测试，同时现有的阅读器、状态恢复、手势、容错性、内容策略和聊天测试仍全部通过。

## 文档和运营变化

- 更新架构和内容策略文档，明确区分已实现的演示版与计划中的生产目标。
- 更新 `.env.example` 和 `README.md`，记录阶段 0 的功能/配置边界和契约检查命令。
- 新增专用的 CI `contract` 作业，通过完整 Git 历史进行基线构建产物的兼容性比较。

## 退出条件证据

- **演示流程未变：**所有原有 Rust 和 Flutter 测试均通过；不存在账户 UI 或账户数据表；功能开关默认关闭。
- **API 测试夹具未变：**现有运行时断言和线上传输序列化器均原样通过；新构建产物只记录这些结构，不会取代它们。
- **发布检查：**`./scripts/check.sh` 成功退出。
- **OpenAPI 覆盖：**受检文档中恰好包含现有的十个健康检查/论文路由；如果出现未记录的路由漂移，路由覆盖测试将失败。
- **不对外开放账户功能：**无论阶段 0 的功能开关取何值，都不会注册 `/v1/me`、文献库、评论或屏蔽路由。

## 留待后续阶段处理的已知风险

- 本报告刻意不实现阶段 1–6 的产品行为。
- 运行时功能清单必须仅在相应的服务端安全链路完整实现时才能扩展；仅有功能开关并不构成授权。
- OpenAPI 响应 schema 已经编译期和回归检查，但未来的账户 DTO 必须继续遵守相同的受检构建产物规范。
- 设备级导航和启动动效验收测试属于阶段 1，因为阶段 0 不包含任何导航或视觉变更。
- 实际 PostgreSQL 断言仍需在 CI 中确认，或在设置 `TEST_DATABASE_URL` 后于本地重新执行。此阶段的集成本地检查只覆盖了这些测试的构建和守卫条件，未执行其数据库测试主体。
- 推送项目时，必须将本地基线标签与仓库 refs 一同发布；本阶段未进行任何远端变更。
