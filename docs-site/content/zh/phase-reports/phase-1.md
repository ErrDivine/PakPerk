# Production v0.0 第 1 阶段报告

**阶段：** 应用壳层、设计系统与启动流程
**状态：** 已完成
**完成日期：** 2026-07-31
**起始提交：** `44cc93f`

本报告记录第 1 阶段的实施结果和自动化证据。它并不声称账户、Library、评论、Drift 缓存、内容审核、运营或应用商店发布阶段已经完成。

## 应用壳层与路由

- 新增 `go_router` 17.3.0，并通过 `StatefulShellRoute.indexedStack` 实现恰好两个 Material 3 主入口：Read 和 You。
- 新增 Section 2.4 要求的平板适配，完成日期为 2026-08-03。紧凑宽度仍使用底部 `NavigationBar`；达到或超过 600 逻辑像素时，则使用位于前侧、适配安全区域并显示 Read/You 标签的 `NavigationRail`。两种表现形式调用同一套分支切换、重复选择和恢复路径；该侧边栏的层级顺序还能确保处于活动状态的嵌套路由不会让它从语义树中消失。
- 在 Read 内保留现有的关联论文页面导航器，使论文访问轨迹、横向阶段、滚动偏移、准备意图和“返回”行为继续保持完全一致的恢复语义。
- 持久化保存所选分支。切换分支会保留 Read 中的论文和 You 中的嵌套路由；再次选择 Read 会弹出嵌套论文，而不会重置 Feed 索引。
- 将论文聊天移到壳层之上的根路由。它只处理一次键盘 inset 和底部安全区域，覆盖导航栏，并能恢复已打开的聊天而不再次发出准备请求。
- 新增根级评论路由。第 1 阶段不提供评论编辑框；内部链接和公开链接会解析经过验证的论文元数据，并显示对应论文且明确标注为已停用的界面。
- 新增如实反映状态的访客 You、设置、认证、Library、评论、删除、法律、社区和支持界面。账户功能关闭时，其中的控件不会执行凭据操作或写操作。

## 深度链接

- 为 `pakperk://paper/...` 和 `https://pakperk.app/p/...` 新增经过 UUID 验证的入口，其中也包括论文评论链接。
- 新增现代和旧版 arXiv 格式解析、安全的编码斜杠传输，以及通过现有精确 ID API 路由完成的 `/arxiv/:arxivId` 解析。
- 从公开论文/arXiv 入口打开时，会获得新的阅读器状态键并始终从 Abstract 开始。从任一公开入口打开的关联论文都会压入其来源页面之上；返回操作会回到来源论文的 Connections 阶段，而不会污染已经恢复的 Read 栈。
- 绝对 URL 只接受确切的生产 HTTPS 源。凭据、替代端口、HTTP、查询参数、片段、路径穿越、多余路径段、格式错误的 UUID/arXiv 值和恶意源，都会在发出论文请求前以失败时默认拒绝的方式终止处理。
- 已注册 Android 自定义链接/应用链接和 iOS 自定义链接/Universal Links。尚未完成的外部域名关联及已签名真机操作流程记录在 [`mobile-app-links.md`](../mobile-app-links.md) 中。

## 启动与持久化交接

- 新增明确的 `bootstrapping -> localReady ->
  authenticatedSessionChecked -> ready` 控制器，并提供可恢复的超时、重试和公开缓存修复状态。
- 应用构造不再等待网络。会话身份、恢复数据和设备上首个缓存 Feed 会并发读取；设备缓存为空时，回退到内置 Feed。在挂载由数据驱动的 Widget 树之前，缓存内容会先按照配置的全文策略进行遮蔽。
- Feed 控制器会同步注入初始状态；如果启动流程已经提供快照，构造函数就不会发出请求。第一个可用 Flutter 帧完成后，恰好启动一次重新验证。启动流程绝不会调用论文准备。
- 修复操作会清除可重建的 Feed、论文、派生数据和聊天偏好设置，同时保留匿名身份和导航恢复数据。第 3 阶段会将该边界扩展到安全的账户凭据。
- 通过 `flutter_native_splash` 2.4.8 新增生成的浅色/深色 Android 与 iOS 启动资源，以及静态居中的论文图标。
- 新增基于真实内容的开场过渡：冷启动 620 ms、深度链接启动 280 ms、减弱动态效果时交叉淡入淡出 140 ms，暖启动或恢复状态时不重放。动画最终显示真实的缓存 Read 树，而不是模拟界面。

## 设计系统与无障碍

- 抽取纸张色、苔藓色、赭黄色的浅色/深色调色板，以及字体、间距、圆角、层级、尺寸、动效、语义状态角色和骨架屏角色。
- 为按钮、卡片、芯片、导航、底部工作表、输入字段、Snackbar 和对话框添加主题，并提供带内边距的 Material 触控目标尺寸。
- 自动化覆盖会检查前景对比度、所选入口/阶段的语义信息、最小触控目标、访客状态的真实性、200% 文字缩放、减弱动态效果、键盘 inset，以及错误/离线状态的实时播报区域。
- Abstract 正文使用 `Text`，而不是 `SelectableText`。在生产壳层下，Flutter 的文本选择识别器会截获阅读器必需的横向阶段手势；文本选择不是 Production v0.0 的要求，而确定性的阶段翻页才是。

## 退出条件证据

- **Read/You 状态保留：** 控制器、Widget、平台恢复、分支重复选择和系统返回测试会保留分支路由、Feed 索引、阶段、准备意图与滚动状态。
- **自适应主导航：** 一项聚焦 Widget 回归测试会把同一个已挂载壳层从 390 像素的手机视口调整到 1024 像素的平板视口，验证恰好两个入口、所选分支的连续性、顶部/底部安全区域几何位置，以及所选入口的语义信息。
- **关联论文恢复：** 原有 Feed/恢复测试继续通过；新增的 UUID 和 arXiv 公开路由往返测试会保留来源 Connections 视图。
- **编辑框几何位置：** 根聊天测试断言导航栏被覆盖、键盘 inset 恰好应用一次，并且编辑框保持可见。
- **启动模式：** 冷启动、缩短的深度链接启动、暖启动、减弱动态效果、超时、迁移失败、重试、修复、过期尝试和首帧刷新测试均已通过。过渡时长常量不超过 700 ms。
- **没有虚假账户行为：** 访客 You 以及第 1 阶段的每一个未来功能路由都会说明对应服务已停用；账户关闭时，评论界面不包含 `TextField`，登录界面也没有回调函数。

## 推迟的真机与发布验证

- 原生界面到 Flutter 界面的闪屏连续性、规定参考设备上的启动耗时、Android 手势导航与三键导航、iPhone 主屏幕指示条和硬件键盘行为，都需要通过真机测试。
- `pakperk.app` 必须先发布最终签名的 Android asset links 和 Apple app site association，Universal Links 才能达到发布就绪状态。
- 应用图标仍需在第 6 阶段生成最终发布品牌版本，并接受应用商店审核；第 1 阶段只包含原生启动资源。
- SharedPreferences 中的 arXiv 回退查找采用线性搜索，启动过程按原样使用已存储的 Feed 数据行。第 2 阶段会用带索引的 Drift 数据表替换批量存储，并在常规仓库重新验证时合并单独缓存的更新版论文数据行。
- 实际 PostgreSQL 断言仍需在 CI 中运行或提供 `TEST_DATABASE_URL`；本阶段不更改后端 schema 或服务器行为。
