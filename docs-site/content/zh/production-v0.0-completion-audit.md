# Production v0.0 完成情况审计

**状态：** 仓库实施已审计；公开/商店发布未被接受

**审计日期：** 2026-08-03

**最后重新验证：** 2026-08-09

**权威依据：** [规范实施计划](../pakperk_production_v0_0_implementation_plan.md)保持规范性

本文档把规范的阶段退出标准、跨阶段验收场景以及 Production 完成定义，映射到仓库中已存在的证据，以及仍必须在仓库之外产出的证据。它是一份证据索引，不能替代规范计划、发布批准，或启用生产功能开关的许可。

## 分类与发布边界

- **R——仓库已证明：** 实施以及确定性、集成、技术契约或参考栈证据存在于仓库中。
- **P——受保护/外部：** 完成需要凭据、已部署系统、受保护环境、已签名产物、物理设备、代表性流量，或源代码控制无法制造的不可变结果。
- **H——人工批准：** 完成需要可问责的操作人员、法务、隐私、内容、安全、UX 或商店判断。

`R/P` 表示源实施已存在，而受保护门禁仍处于开放状态。它绝不表示规范要求已在生产环境中通过。已纳入版本控制的工作流 YAML、验证器、测试夹具、模拟器运行、参考 Keycloak/PostgreSQL 演练，以及缺少可取回的通过产物的工作流分发，都属于 **R**，而不是 **P**。人的陈述、工单编号、可变 URL 或某个断言的哈希，都不是 **H** 证据。

阶段 0–5 是在其范围化报告下已接受的仓库里程碑。第 6 阶段拥有暗发布的仓库实施，但其生产与商店退出标准仍处于开放状态。因此，Production v0.0 **尚未完成**，并且在下方每一个适用的 **P** 与 **H** 条目都拥有不可变证据之前，公开账户/评论开关与商店发布都必须保持封锁。此次审计识别出的已知本地可实施缺口，已反映在仓库中。检查点 `d83ee84` 处的最后一个完整本地规范测试工具，通过了全新数据库 Rust 工作区、Flutter 分析以及全部 610 项当时锁定的测试、每一个 Android 调试与 iOS 模拟器构建变体、严格的产物检查、31 项浏览器测试、Helm 验证，以及可选启用的 Collector 导出 E2E。后续的当前代码树移动端变更，通过了 Dart 格式化、完整分析，以及六个已修改评论套件中的全部 49 项测试，而其扩展后的完整 Flutter 套件，仍是当前源代码的一项门禁。当前公开的用户/开发者指南、经整理的 site 打包、18 场景的公共边缘技术契约，以及封闭式验证器，也已通过评审；浏览器执行仍限于最后一个完整检查点，因为此运行器无法启动 Chromium。全新的隔离 Keycloak/PostgreSQL 参考运行，还通过了完整的账户删除 worker/台账/对账矩阵与评论/内容审核/IdP 中断矩阵，并完成了脱敏与清理。该证据无法证明不存在任何进一步的本地缺陷，也不能减少或替代任何受保护执行或人工批准。

当前代码树还针对五个非恢复生产批准清单、其最终渲染的部署前捆绑包、经脱敏的暗部署溯源信息、受保护服务演练，以及三重门禁运营证据捆绑包，拥有失败即关闭的规范源代码技术契约。它们的聚焦回归测试通过，但本次本地工作并未产出任何生产批准清单、真实集群捕获、预发布冒烟产物、提供商/服务演练、迁移、实时遥测、签名设备性能/崩溃观测，或可问责的平台决定；这些行仍为 **P/H**。

受保护的移动端工作流要求确切的 `main` 修订版本、根导入的内容寻址候选版本与已签名发布溯源信息清单、固定的根拥有验证器与驱动器字节、一次短时效的根拥有专用/临时运行器会话证明，以及四个确切的物理角色：Android 手势、Android 三按钮、iPhone 主页指示器，以及物理键盘 iPad/第二同步。候选检出是仅数据输入：候选提供的程序不会在带凭据的运行器会话中执行。其 schema-v6 产物要求全部 42 个有序场景及其确切的角色分配、317 个有序断言 ID、254 个闭合整数指标、确切的平台产物/应用/签名者/团队绑定、从不同的根证明承诺重新计算的四个挑战作键的物理身份哈希，以及一个全新的运行挑战/ID/尝试/时间窗口。其 schema-2 源绑定与保留的坐标，还绑定确切的预发布 API、应用链接、OIDC 签发方与客户端身份。根导入的候选版本与溯源信息，是规范的 schema-v4 清单，携带着相同的嵌套 schema-v6 功能绑定，覆盖四个 To Read First 开关、全部十个 Plan 02 移动开关，以及全部十个 Plan 03 移动开关。驱动请求还绑定确切的场景/断言/指标计数，以及规范技术契约 SHA-256 `7483820afc6b2111f4886177dd120e72ab8ca47164757ca1eda9e10f64d70ad5`。v6 标记覆盖全新访客安装与 arXiv 交接、离线进程死亡阅读、跨设备移除/墓碑收敛、完整的评论/举报重放、无效刷新、物理链接、签名设备保护、缓存边界，以及浅色/深色路径。它们还要求跨平台队列权威性/FIFO、失败即关闭的待处理/离线/重置/移除、账户范围的分阶段发布再验证，以及确切/标题/错误/重试/幂等的 Add Paper 覆盖。另外五个有序场景，覆盖 Plan 02 的 Search/Lookup/Explore/已保存查询、研究资料分离/重置、有证据支持的 Why/反馈、不涉及队列写操作的阅读简报进度，以及订阅/通知安全。再有十个场景，覆盖 Deep Reader 导航、Passport、语义分面、视觉来源完整性、检查点隔离、标注/证据持久性、研究记忆、版本差异/重锚定安全、Assistant v2 证据完整性，以及队列安全的大型文档。其编排与验证器是仓库证据，而不是一次通过的运行。这些场景不能替代自动化套件，也不能证明每一种功能排列；单独的受保护预发布、隐私、可观测性、分阶段发布以及外部门禁仍然适用。只有经认证的根侧溯源信息/会话导入，以及针对已安装候选版本的一次通过的受保护产物，连同环境批准，才能满足对应的 **P** 行。参见[移动端发布运行手册](mobile-release.md)。

## 每一个未关闭的 P/H 门禁所需的不可变证据

每一个受保护证据对象，都必须存储在经批准的不可变发布系统中，并且可以通过其内容 ID 取回。除非适用更严格的封闭工作流 schema，否则其规范清单必须包括：

- 清单字节的 SHA-256 内容 ID，以及每一个附加产物的 SHA-256 摘要；
- 确切的 40 字符源代码修订版本、应用版本/构建、Helm chart/应用版本，以及范围内每一个已部署或候选镜像/产物摘要；

- 工具、扫描器、驱动器、策略、配置与工作流身份/摘要；
