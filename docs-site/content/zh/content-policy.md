# 全文和 arXiv 数据政策

Pakperk 使用 arXiv 元数据并为每条记录链接回其原始的 arXiv 页面。Pakperk 并不隶属于或被 arXiv 赞助。

## 生产版本 v0.0 政策状态

当前的生产迁移包含一个功能受控的公开论文评论实现。它包括认证发布、明确的条款和社区指南接受、标准化的纯文本验证、独立的评论和用户举报、持久的用户屏蔽、审计的管理操作、共享的速率限制以及稳定的支撑合同。举报永远不会创建屏蔽或更改可见性。评论举报功能默认保持关闭。仓库现在提供账户删除、托管政策/支持、保留执行、遥测和操作控制，但公开创建在这些控制在目标环境中执行且法律/存储/管理所有者批准证据之前仍然被禁止。这是一个已实现的暗启动功能，而不是声称公开用户生成内容已上线。

当在生产版本中启用评论时，评论是公开的用户生成内容。它们不是私人笔记或学术认可；产品会披露这一事实，并提供单独的 **举报评论**、**举报用户**、**屏蔽用户**、支持和作者移除途径。
`COMMENT_CREATION_ENABLED=false` 仅停止新发布，以确保阅读和安全操作仍然可用。权威的产品、管理、保留和删除要求在
[生产 v0.0 计划](production-v0.0-plan.md) 和
[ADR 0004](adr/0004-public-comments-and-moderation.md) 中；具体的网络和设备行为在
[评论和管理合同](comments-and-moderation.md) 中。

`FULLTEXT_POLICY` 有两种模式：

- `prototype` 用于本地研究和演示。一个工作者下载一个经过验证的 arXiv PDF 到一个随机的临时路径，从不提供该 PDF，解析它，并在标准化后删除它。
- `strict` 仅在缓存的论文许可允许配置的重用时才发布引言/全文推导功能。否则，论文保持为仅包含元数据，并带有外部 arXiv 链接。

工作者在创建工件前检查此政策，API 每次提供推导内容时再次检查此政策。第二次检查是有意为之的：将部署从 `prototype` 切换到 `strict` 立即隐藏旧功能，并拒绝未知或不支持的许可证的持久引言、聊天和连接数据；不需要数据库清理。

移动构建有一个对应的编译时开关：

```sh
--dart-define=PAKPERK_FULLTEXT_POLICY=strict
```

与后端严格模式一起使用。当离线时，严格构建保留元数据和原始 arXiv 链接，但从不回退到设备缓存或捆绑的推导内容。后端政策拒绝使用 HTTP 403 响应码 `FULLTEXT_POLICY_DENIED`，并且永远不会被视为临时回退信号。

元数据、许可证、精确-ID 查找和搜索结果会被缓存。所有旧版 arXiv API 请求都会通过一个数据库支持的跨进程网关，默认情况下最小间隔为三秒，并尊重 `Retry-After`。

在公开发布之前，推导全文的显示和保留政策需要由合格的法律顾问审查。原型开关不是法律决定。
