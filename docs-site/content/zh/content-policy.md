# 全文与 arXiv 数据政策

Pakperk 使用 arXiv 元数据，并为每条记录提供指向其原始 arXiv 页面的网址。Pakperk 与 arXiv 不存在隶属关系，也未获得 arXiv 赞助。

## 生产版本 v0.0 政策状态

当前的生产迁移包含一套由功能开关控制的公开论文评论实现。它涵盖已认证发帖、明确接受《条款》和《社区指南》、规范化纯文本校验、彼此独立的评论举报与用户举报、持久化用户屏蔽、受审计的内容审核操作、共享限流，以及稳定的支持技术契约。举报绝不会自动创建屏蔽关系或改变可见性。创建评论默认保持关闭。仓库现已提供账户删除、托管政策及支持路由、保留政策执行、遥测和运营控制；但在目标环境中实际演练这些控制，并由法律、应用商店政策和内容审核负责人批准相关证据之前，仍禁止公开创建评论。这是一项已经实现但尚未公开启用的功能，不代表公开用户生成内容已经上线。

在生产构建中启用评论后，评论属于公开的用户生成内容。它们既不是私密笔记，也不代表学术认可；产品会明确披露这一点，并分别提供 **举报评论**、**举报用户**、**屏蔽用户**、支持路由和作者自行移除内容的路由。
`COMMENT_CREATION_ENABLED=false` 只会停止发布新评论，确保读取和安全操作仍然可用。权威的产品、内容审核、保留及删除要求见
[Production v0.0 计划](production-v0.0-plan.md)与
[ADR 0004](adr/0004-public-comments-and-moderation.md)；具体的网络和设备行为见
[评论与内容审核技术契约](comments-and-moderation.md)。

`FULLTEXT_POLICY` 有两种模式：

- `prototype` 用于本地研究与演示。worker 把经过验证的 arXiv PDF 下载到随机临时路径；系统绝不对外提供该 PDF，并会在解析和规范化完成后将其删除。
- `strict` 只有在缓存的论文许可证允许按配置方式复用内容时，才会提供引言或其他基于全文派生的功能。否则，论文只保留元数据以及指向 arXiv 的外部链接。

worker 在创建产物前检查该政策；API 每次提供派生内容时都会再次检查。有意保留第二次检查，是为了让部署从 `prototype` 切换到 `strict` 后立即隐藏既有功能，并拒绝为许可证未知或不受支持的论文继续提供已持久化的引言、聊天与关联数据；无需清理数据库。

移动端构建提供对应的编译期开关：

```sh
--dart-define=PAKPERK_FULLTEXT_POLICY=strict
```

该开关应与后端的 strict 模式配套使用。离线时，strict 模式构建仍保留元数据和原始 arXiv 链接，但绝不会回退到设备缓存或应用包内的派生内容。后端因政策拒绝请求时，会返回 HTTP 403 和错误代码 `FULLTEXT_POLICY_DENIED`；客户端绝不能把它当作可临时降级的信号。

系统会缓存元数据、许可证、按指定 ID 查询的结果以及搜索结果。所有旧版 arXiv API 调用都通过由数据库支持的跨进程门禁；默认最小请求间隔为三秒，并遵循 `Retry-After`。

公开发布前，基于全文派生内容的展示和保留政策必须经过合格法律顾问审核。prototype 开关本身不构成法律判断。
