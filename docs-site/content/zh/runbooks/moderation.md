# 评论内容审核运行手册

**负责人：**指定的 Pakperk Trust & Safety 值班运维人员。
**备份：**生产事件指挥官。
**公开启用状态：**控件已实现但保持封锁，直到支持路由、账户删除、保留、商店评审、监控、人员配备和本运行手册都在目标环境中演练过。

## 响应时限

| 类别 | 示例 | 分流时限 | 初始操作 |
|---|---|---:|---|
| 危急 | 可信威胁、儿童性剥削、迫在眉睫的自我伤害、暴露的凭据/私人位置 | 1 小时 | 保留最少证据、隐藏、立即上报 |
| 高 | 人肉搜索、定向骚扰、仇恨言论、未经同意的亲密内容、恶意链接 | 4 小时 | 隐藏或保留待审、检查账户历史、按需上报 |
| 标准 | 垃圾信息、冒充、版权、普通滥用 | 2 个工作日 | 评审举报并应用既定操作 |

只有在生产告警/工单集成上线后，时限才开始计算。操作人员通过 `pakperk-admin` 记录每个决定；直接 SQL 不是普通的内容审核工作流。

## 队列工作流

1. 查看评论举报和用户举报队列及其合并的最老时限指标，不打印评论正文或举报详情。对评论举报使用 `comments list --status open`，对用户举报使用 `user-reports list --status open`。
2. 选择一个举报 ID。对关联评论使用 `comments inspect <comment-id>`，对单条用户举报使用 `user-reports inspect <report-id>`。
3. 使用稳定的理由/操作代码进行分类；不要把内容复制到聊天、日志、shell 历史或事件标题中。
4. 当继续展示会造成可信伤害时立即隐藏。对于高/危急级别的反转，只有在二次确认后才恢复。
5. 使用 `reports resolve` 或 `user-reports resolve` 处置/驳回举报并记录该操作。封禁屡犯或严重违规者；只有记录原因后才能恢复资格。
6. 把法律请求、儿童安全材料、可信威胁或紧急隐私暴露上报给已配置的合格值班运维人员。不得下载或再分发非法材料。
7. 验证审计事件、队列时限和公开结果。

`pakperk-admin` 从经提供商认证的操作人员派生审计操作者；调用方无法提供操作者标签。调用它之前，先完成一次近期的 OIDC 认证，并把短期访问令牌放入绝对路径、仅限所有者（`0600`）、非符号链接的常规文件。配置 `ADMIN_OIDC_ISSUER_URL`、`ADMIN_OIDC_AUDIENCE` 和 `PAKPERK_ADMIN_ACCESS_TOKEN_FILE`。把 `ADMIN_AUTHORIZED_USER_IDS` 设置为以逗号分隔、受变更控制的允许列表，其中是当前 Trust & Safety 操作人员的规范本地 Pakperk 用户 UUID；允许列表之外的已认证账户没有管理权限。除非身份所有者批准了另一个有界的允许列表，否则让 `ADMIN_OIDC_ALLOWED_ALGORITHMS` 保持其 `RS256` 默认值。`ADMIN_AUTH_MAX_AGE_SECONDS` 默认为 15 分钟，可以是 60–3,600 秒。普通 HTTP 发现是被禁止的，除非使用 `ADMIN_OIDC_ALLOW_INSECURE_HTTP=true` 显式启用仅限环回的开发签发方；绝不在预发布或生产环境中启用它。

启动时，CLI 会验证发现/JWKS 传输、签名、签发方、受众、过期时间以及 OIDC `auth_time` 声明。令牌 `iat` 绝不会被接受为近期交互式登录的证明。随后它会把已验证的 `(issuer, subject)` 映射到一个现有的活跃 Pakperk 账户，而不预配或更新账户，并对照操作人员允许列表检查本地 UUID；该 UUID 就是被审计的操作者。缺失 `auth_time`、过期、未知、未授权、被封禁、删除待定、文件不安全或其他无效身份都会在任何命令运行前失败即拒绝。在操作人员会话结束后移除令牌文件；如果它可能已暴露，则遵循事件运行手册。撤销操作人员时，先从部署密钥/配置中移除该 UUID 并滚动管理作业，然后再停用身份提供商账户。

列表命令绝不打印完整正文。只有显式的 inspect 命令可以显示单条正文，并且操作人员必须使用临时终端，数据库和身份凭据都在 shell 历史之外提供。绝不把令牌、电子邮件地址或自选的操作者值作为命令参数或环境变量传递。

## 验收与生产就绪证据

手动的 `live comments acceptance` 工作流是一次带环境门禁、只针对 `main` 顶端的一次性参考 PostgreSQL 和 Keycloak 服务演练。成功的运行会演练独立的移动端和 `pakperk-admin-dev` PKCE 受众，在管理边界拒绝 API 受众令牌，拒绝位于本地允许列表之外的有效管理受众身份，把操作归因到允许列表中的操作人员，保留紧急关闭开关安全操作，并清理其测试夹具。其闭合产物被归类为一次性参考证据，而不是预发布或公开启用批准。其域分隔的参考 ID 有意不是有效的生产 Helm `releaseEvidence.moderationReadinessId`。绿色工作流是有用的回归证据，但绝不会授权公开评论。

分发之前，仓库管理员必须在 GitHub 中验证 `live-comments-acceptance` 环境已配置必需的审核者，并将部署分支限制为 `main`。YAML 环境声明和作业级分支检查不会创建或证明这些带外保护设置。不要把来自未保护或配置错误环境的运行当作已评审的参考证据。

因此保留的产物总是记录 `manual_ci_disposable_reference`，绝不是受保护环境的声明。即使管理员已正确配置并批准 GitHub 环境，该分类仍保持手动；审核者和部署分支证据属于 GitHub 的外部运行记录，而不是这个一次性载荷。

受保护的预发布内容审核就绪必须改为把精确的候选修订和已部署镜像摘要绑定到以下所有各项：

- 目标签发方专用的操作人员受众、近期认证策略、当前允许列表、移动端/API 受众拒绝、非允许列表操作人员拒绝，以及可归因的审计 UUID；
- 真实评论和用户举报队列；同身份重复提交评论举报返回规范结果且恰好有一个持久举报；显式检查、隐藏/恢复、举报处置、封禁/恢复资格、创建紧急关闭开关、高风险保留、提供商中断回退以及访客读取可用性；
- 目标内容审核适配器/凭据、路由到有人值守的值班安排的队列时限和失败告警、上文的响应时限，以及演练过的升级流程；
- 公开 UGC 之前需要的目标支持、法务、删除、保留、备份/恢复和事件依赖项；以及
- 脱敏的日志/遥测，以及所有者、UTC 窗口、环境、候选版本、不可变证据位置和 Trust & Safety 批准。

只有覆盖该目标环境矩阵的内容寻址记录才能作为 `moderationReadinessId` 录入；缺失、失败、仅参考或部分演练的证据会让评论创建保持禁用。

## 紧急控制

- 设置 `COMMENT_CREATION_ENABLED=false` 以停止新帖，同时保留阅读、评论/用户举报、屏蔽、作者移除和内容审核。
- 只有当整个评论界面必须撤下时才设置 `COMMENTS_ENABLED=false`；访客论文阅读必须保持健康。
- 疑似凭据暴露遵循事件运行手册和密钥轮换；绝不把凭据粘贴到举报中。

`API_ORIGIN_HASH_SECRET_FILE` 是对轮换敏感的滥用控制密钥，不是 IP 存档。它必须保持为仅限所有者、非符号链接的常规文件，包含 32–4,096 个非占位字节。替换会改变每个源摘要，因此会启动全新的源桶（账户桶不受影响）。在队列和滥用速率仪表板有人值守时谨慎轮换；滚动每个副本，旧部署密钥只保留到先前副本和速率窗口过期为止，然后销毁它。验证期间绝不记录任何一个密钥或原始对端地址。

`API_CURSOR_ENCRYPTION_KEYS_FILE` 必须对 API 和 `pakperk-admin` 都可用，这样一个副本或调用签发的游标才能被另一个继续使用。它是一个仅限所有者、非符号链接的密钥环，最多包含八行 `key_id:base64(32 random bytes)`。分两个滚动阶段轮换它：在旧密钥保持第一位时追加候选密钥并滚动每个 API/管理使用方；然后把候选密钥移到第一行并再次滚动每个使用方。晋升会改变 Feed 的非密钥游标验证器纪元，因此携带晋升前 ETag 的条件首页请求必须返回带新游标的 `200`，而不是通过 `304` 保留旧游标。在每个使用方都完成晋升上线后，验证该再验证行为以及返回的游标能成功分页。然后在最长预期的进行中分页窗口内保留较旧的密钥，并且只有在旧游标可以安全过期后才移除它们。在晋升上线和此再验证检查完成之前，绝不要移除旧密钥。这一顺序让滚动部署的两半都能解密每个新签发的令牌。移除密钥会立即使其未完成的 Feed、论文库、评论和内容审核游标失效；绝不把请求源密钥用作游标密钥材料。

`API_TRUSTED_PROXY_CIDRS` 必须只包含从入站控制器链实际观察到的源范围。只有当直接对端位于这些范围内时，API 才接受 `X-Forwarded-For`，并从右到左遍历链路；格式错误或缺失的元数据回退到直接对端。更改该列表之前，确认 NetworkPolicy 仍然只放行已评审的入站控制器命名空间/pod，验证控制器会追加连接地址，并在预发布环境中同时测试正常客户端和伪造的最左侧条目。绝不添加全网范围的地址段。

重新启用创建之前，清除事件原因，排空未处理队列，测试一条已发布并保留的预发布评论，确认告警/时限指标，并记录批准的操作人员和时间戳。
