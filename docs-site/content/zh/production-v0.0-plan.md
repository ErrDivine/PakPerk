## 计划的管辖范围

Production v0.0 将现有的模块化 Rust 单体服务与 Flutter 阅读器演进为可上架的早期产品。它保留访客阅读和当前的论文处理生命周期，同时按可发布阶段增加：

- 持久化的 Read / You 应用外壳与无障碍启动动效；
- 使用 Drift/SQLite 存储关系型离线缓存、草稿和持久化待同步队列（outbox）；
- 采用 PKCE 的 OIDC Authorization Code、安全令牌存储，以及与身份提供商无关的后端验证（以 Keycloak 作为参考部署）；
- 为已登录用户同步 To Read 收藏；
- 公开、扁平的论文评论，以及条款接受、举报、屏蔽、内容审核、账户删除和运营责任；
- 基于 PostgreSQL 的共享限流、契约检查、可观测性和生产运维。

规范计划中的稳定 API 名称（包括由成功的 v0.0 语义保留的名称）索引在 [API 错误目录](api-error-catalogue.md)中。

## 不可妥协的护栏

规范计划的执行契约具有约束力。尤其要遵守以下要求：

- 不得重写当前论文流水线，也不得削弱其限定处理代际的产物边界与全文策略边界；
- 绝不能通过启动、预取、缓存加载或账户同步来触发论文准备；准备仍只能由用户确认进入阅读器或明确重试触发；
- 保留匿名浏览和阅读；只有云端所有权操作及内容审核敏感操作才要求认证；
- 不得存储密码，也不得把访问令牌/刷新令牌放入常规偏好、SQLite、日志、分析、崩溃报告或身份提供商快照；
- 确保重试写入具备幂等性，并采用扩展后收缩式数据库迁移；
- 在所有必需的安全控制上线前，不得开放公开评论；
- 未撰写 ADR 不得新增网络服务；在此里程碑中，PostgreSQL 仍是共享同步、任务和速率限制的事实来源。

## 阶段记录

Phase 0 创建安全的扩展点，但不改变可见的演示行为。其文档产出是本计划入口和 [`docs/adr/`](adr/) 中的 ADR。实施产出包括路由/中间件/DTO 与仓库层拆分、初始 OpenAPI、类型化功能标志，以及经过验证的预发布/生产配置。仅凭 Phase 0 不会引入账户、账户表或公开控件。

实施证据记录在 [Phase 0 报告](phase-reports/phase-0.md)中。

Phase 1 建立双目的地移动端框架、保留状态的路由、经过验证的论文/arXiv 链接、访客 You 界面、根级上下文路由、设计令牌、浅色/深色主题、原生启动资源，以及有界且缓存优先的启动状态机。账户、Library 和评论仍明确处于禁用状态；相关路由是如实说明状态的占位页，而不是声称已交付一部分产品能力。实施与验证证据记录在 [Phase 1 报告](phase-reports/phase-1.md)中。

Phase 2 使用带版本的 Drift/SQLite 数据库取代 SharedPreferences 中的批量内容，以事务方式导入并移除有效的旧版数据块，并增加确切的多页信息流持久化、arXiv 版本与处理代次一致性、有界淘汰和生命周期安全的物理压缩。专用且仅服务信息流的预取协调器实现合并并发请求的提前缓存、查询失效、重试/退避和不含内容的指标。后端和移动客户端新增不透明 ETag/`If-None-Match` 再验证，并以无正文的 `304` 响应。实施已经存在；最终集成门禁和原生门禁均在 [Phase 2 报告](phase-reports/phase-2.md)中记录为通过，本阶段已完成。

Phase 3 在保留访客阅读的同时加入可选 OIDC 账户。当前实施包括有界且与身份提供商无关的发现/JWKS 验证、事务性 JIT 账户映射、带版本的资料更新、首个共享 PostgreSQL 速率限制桶、原生 AppAuth 与安全令牌存储，以及可选的 Keycloak 开发配置。它还实现了可感知账户状态的 You/引导流程。只有启用账户后才会注册 `GET` 和 `PATCH /v1/me`；Library、评论和删除功能仍不存在。仓库级门禁、原生构建、真实 PostgreSQL 场景和真实 Keycloak/Mailpit PKCE 流程均已通过，因此 Phase 3 **已完成**。证据记录在 [Phase 3 报告](phase-reports/phase-3.md)中。

Phase 4 **已完成**。其有界契约包含单一 `to_read` 集合、已认证的列表与账户范围修订变更读取、幂等收藏/移除写入、保留 90 天且带安全重置信号的墓碑，以及移动端乐观待同步队列（outbox）收敛。其他账户的变更绝不会推进某位读者的水位线，也不会通过该水位线泄漏。Library 路由同时要求账户和 Library 门禁；独立写入门禁可以冻结变更操作，而不移除读取能力，也不影响公开论文访问。详细契约见 [To Read Library 同步](library-sync.md)；仓库、真实 OIDC/PostgreSQL、双客户端、不触发准备、写入熔断和原生构建证据记录在 [Phase 4 报告](phase-reports/phase-4.md)中。

Phase 5 作为仓库能力**已完成**。它实现了扁平的公开论文评论、当前策略接受、确定性且与身份提供商无关的内容审核、共享的用户/请求来源限制、独立的评论举报、用户举报、屏蔽和作者操作、经过审计的审核员管理工具、账户范围的移动端页面/草稿/屏蔽，以及独立的评论创建紧急关闭开关。真实双用户 PostgreSQL/Keycloak 和身份提供商故障证据记录在 [Phase 5 报告](phase-reports/phase-5.md)中。该功能仍默认关闭；公开启用还要求目标环境提供内容审核、删除、法律、监控和应用商店策略证据。

Phase 6 的**仓库实施已作为暗发布候选版本存在**。它包括移动端/API/Web 近期认证删除流程、有界 Keycloak 管理、带租约的删除 worker、独立签名的恢复台账与重放、保留期清理/清除控件、生产 Helm 拓扑、OTLP 与具备验证能力的移动遥测网关、内容寻址的生产告警策略，以及绑定功能、已部署镜像摘要、Chart/应用身份和法律策略版本的不可变发布证据契约。它还包括先扫描再发布且绑定精确 SHA 的后端/站点镜像自动化与仅摘要晋升、安全/源码/原生 SBOM 工作流（附经审查的运行时依赖图完整性），以及锁定的原生/移动发布工具，包括 MRI Ruby 3.4.10、RubyGems 4.0.17、Flutter 3.44.8/framework `058e0af2c2b57e369d905a03ac9748b0ebf543c6`/Dart 3.12.2。它还提供内容寻址的产物/签名溯源信息的签名移动候选版本自动化、受保护的四设备验收通道、策略/支持托管，以及发布、事件、内容审核、删除、可观测性、负载和备份/恢复运行手册。仓库还包含选择性启用的一次性 Keycloak 删除验收工作流、受保护且绑定精确 SHA 的预发布后端负载门禁、针对已配置暗发布部署的手动精确 main 公共边缘验证/证据通道，以及绑定受保护证明和内容寻址证据的闭合双阶段恢复工具。移动端启动/缓存/无障碍加固覆盖统一缓存策略、先显示陈旧内容、无障碍缓存未命中骨架屏、共享论文操作、并发本地/会话工作、重试/修复责任、减少动态效果、稳定后的触觉反馈、200% 文本、对比度和规范 arXiv 操作。仓库和移动端证据记录在 [Phase 6 报告](phase-reports/phase-6.md)与[移动端 Phase 6 报告](phase-reports/phase-6-mobile.md)中。

2026-08-02 的收口审计还用支持旋转的认证加密令牌取代了可读的分页坐标；这些令牌会绑定每个列表的用途以及查看者/筛选范围。该审计将信息流验证器绑定到活跃游标密钥纪元，让共享移动连接状态取决于原始传输结果，在刷新失败后仍保留真实 `401` 的可达性，强制一次性的认证交接，在已认证评论重新加载后提供有界的安全意图恢复，在确认已有网络支持的完整页面之前隐藏评论总数，并将策略接受绑定到每个签名构建中的确切文档。CI 现在会独立解析每个 shell 脚本，而不依赖 Bash 的多参数行为；OpenAPI 兼容性门禁会拒绝单向 schema、响应、回调、Webhook 和序列化回归。在检查点 `d83ee84`，完整规范运行通过了 Flutter 分析及当时锁定的全部 610 项测试、每个 Android 调试风味、每个 iOS 模拟器风味、严格产物检查、全新数据库 Rust 工作区、31 项浏览器/站点测试、Helm、SBOM 与发布契约验证器，以及选择性启用的 Collector 导出 E2E（端到端）测试。锁定套件包括账户重新绑定、删除锁存器、异步意图和缓存清除隔离回归。后续当前工作树的移动端变更通过了格式检查、分析和六个已修改评论套件中的全部 49 项测试，但尚未重放扩展后的完整 Flutter 套件。这些是本地仓库检查；它们不会改变下述外部发布门禁状态。全新隔离参考栈运行也通过了真实 Keycloak/PostgreSQL 账户删除 worker/台账/对账路径，以及双用户加操作员的评论/内容审核/IdP 故障矩阵，并完成脱敏和清理。

不能仅凭源代码证据将 Phase 6 接受为公开/商店发布。一次性参考身份提供商工作流不能替代针对真实秘密管理器、外部台账、备份清单和告警路由的受保护预发布删除验证；有界负载工具也不能替代一次成功的受保护预发布运行。最新的分析器、锁定套件、调试/模拟器产物、站点、Helm 和 Collector 结果都是当前工作树的本地证据。实际的隔离备份/PITR 恢复与删除重放、迁移/回滚演练、已部署预发布/生产遥测汇/保留期和告警适配器/接收器/金丝雀检查、当前联网的安全公告/容器扫描、受保护镜像发布与摘要晋升、对应确切暗发布目标的成功公共边缘工作流产物、实体设备与性能/崩溃窗口、受保护签名、TestFlight/Play 封闭测试上传、审核员账户/备注、法律/内容审查、信息披露和应用商店批准，仍是外部发布门禁；在负责人附上不可变证据前，必须一直将其标记为未通过。
