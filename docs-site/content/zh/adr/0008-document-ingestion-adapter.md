# ADR 0008：学术文档解析器适配器与证据绑定选型

## 状态

已接受并用于 Plan 03 实现。GROBID 仍是生产环境的默认解析器。

## 背景

现有工作进程直接把 GROBID TEI 解析为 v0.0 文档模型。
Deep Reader 需要规范化内容块、章节树、引文、页面映射、插图、表格、公式、术语，
以及稳定的溯源信息。解析器质量会随文档类型而变化；如果只依据少数表现良好的样例
选择解析器，派生产物和重新处理行为将缺乏安全保障。

## 决定

在摄入层引入 `ScholarlyDocumentParser` 适配器边界。
每次成功或终止的解析都会记录封闭枚举的适配器 ID、适配器版本、规范化 schema 版本、
输入生成版本和安全失败类别。规范化、质量检查、溯源信息发布和生成版本取代机制
继续与具体解析器无关。

工作进程选择一个配置好的主适配器。只有显式枚举的失败类别才允许确定性回退。
两个适配器的输出绝不会被静默合并；未来如果引入混合结果，必须记录每个组成对象的溯源信息。

GROBID 继续沿用固定的镜像、超时与 PDF 边界、许可/全文政策、TEI 测试夹具和
参考文献解析行为。Docling 或其他适配器仍受 `DOCLING_EXPERIMENT_ENABLED` 控制。
该实验标志要求启用 `DEEP_READER_ENABLED`，但它本身并不授权更改默认解析器。

## 基准评测决策门禁

候选默认解析器必须在法律用途适当且带版本的语料库上评测。语料库应覆盖双栏布局、
嵌套章节、公式、密集表格、多面板插图、格式错误的参考文献、政策允许的图像密集型输入、
长附录、非常规标题和旧版 PDF。人工标注的真实基准应覆盖顺序、边界、引文目标、
视觉关联、表格结构、公式、页面映射、参考文献、损坏、重复和遗漏。

决策必须绑定语料库及真实基准摘要、适配器/容器及依赖项身份、文档 schema、资源测量、
回退类别、内容政策行为，以及重新处理和回滚结果。仓库中的测试夹具用于验证契约
结构；法律适用性和人工标签属于外部证据，不能由 CI 合成。

## 后果

- 解析器溯源信息成为每个派生产物和缓存键的一部分。
- 更改解析器或 schema 会产生新的生成版本及重新处理决策。
- 无法可靠提取内容时，系统可以终止处理并仅保留元数据。
- 更改默认解析器之前，[分阶段发布运行手册](../runbooks/deep-reader-rollout.md)必须证明金丝雀发布、回滚和版本取代均可正常执行。
- 新的外部解析器镜像必须接受现有的摘要、SBOM、漏洞、许可、网络政策和发布绑定控制。
