# ADR 0004：公开评论与内容审核

**状态：** 已接受并实现；面向公众启用仍受环境门禁控制
**日期：** 2026-07-31

## 背景

Production v0.0 增加了论文级讨论，也就引入了公开的用户生成内容。
如果评论功能缺少举报、屏蔽、内容审核、限流、条款接受、删除和响应流程，
发布后既不安全，也无法获得必要的运营支持。

## 决策

只提供公开、扁平的论文级评论。访客可以阅读已发布的评论；账户状态正常、
拥有公开用户名并已接受《条款》和《社区指南》的已认证用户可以发表评论。
评论采用规范化纯文本，并受到严格的 Unicode 标量值、字节数和 URL 数量限制；
按最新优先排序，不支持 HTML、附件、回复、表态、投票、实时更新或匿名发布。

创建评论时执行确定性校验和反垃圾规则、账户及 IP/设备限流、账户状态检查，
并可调用与提供商无关的服务端内容审核适配器。已实现的远程接缝是 API 经由已审核的
出口发起的一次有界 HTTPS JSON 调用；它既不是移动端 SDK，也不是新的 Pakperk 服务。
可疑或模型无法确定的结果会进入待审核状态或被暂时拒绝，而不会自动发布。
用户可以编辑或删除自己的评论、举报评论或用户，并可另行屏蔽其他作者。
审核员可通过受审计的工具审核举报、隐藏或恢复评论，以及暂停或恢复账户。
全局功能开关可以停止创建新评论，而不影响评论阅读。

## 后果

- 评论功能需要为评论、举报、屏蔽和内容审核事件建立规范化数据表；客户端创建评论时使用稳定的请求 ID 来保证幂等性。
- 发表评论要求 Pakperk 内存在明确的社区政策接受记录；仅在身份提供商的同意页面确认并不够。
- 启用公开功能标志前，产品必须提供清晰的公开内容说明、支持联系方式、举报体验、账户删除能力，并明确举报响应负责人。
- 初始内容审核界面可以是已认证的管理员 CLI，但必须记录操作人和操作内容以供审计；除非明确执行内容检查，否则不得打印内容。

## 安全与运营影响

- 评论正文、举报详情、身份和内容审核元数据属于敏感运营数据：必须从遥测中脱敏，并严格限制其访问权限。
- 服务端校验具有最终权威；客户端计数器和过滤只用于改善体验。渲染后的链接必须安全解析，并具备外部导航防护。
- 幂等机制和受所有者约束的 SQL 可防止重试造成重复写入，也可阻止跨账户编辑或删除。对于私有资源，失败响应应在适当情况下避免泄露资源是否存在。
- 发布门禁要求内容审核操作已经过测试，支持路由真实可用，条款和社区页面就绪，限流与保留/删除政策落实，并已明确事故及举报响应负责人。

## 实现结果

Phase 5 已在现有 Rust 后端和 PostgreSQL 数据库内实现扁平评论、举报、屏蔽、
政策接受、共享限流、规则审核、适配器和内容审核审计模型。API 路由注册与允许发布新评论
使用不同的部署标志。Flutter 客户端在账户与认证纪元写入屏障之后，保存数量有界的
个性化页面、账户范围草稿和持久化屏蔽关系；草稿绝不会进入自动待同步队列（outbox）。
`pakperk-admin` 提供明确的检查和操作命令，生成可归责的审计记录与不含内容的队列指标。
它只向满足以下条件的主体授权：近期 OIDC `auth_time` 映射到状态正常的本地账户，
并且该账户的 UUID 位于受保护的运营人员允许列表中；普通已认证账户无法调用内容审核操作。

仓库现已实现本 ADR 要求的应用内及网页账户删除、保留和恢复重放机制、托管支持与
法律政策路由、遥测流水线，以及告警和运行手册契约。发布门禁并未因此放宽：
在目标环境中实际演练这些机制，并由法律、内容审核、隐私和应用商店政策负责人
最终审核并批准相关证据之前，公开创建评论仍保持关闭。
