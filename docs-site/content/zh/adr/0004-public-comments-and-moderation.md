# ADR 0004: 公共评论和管理

**状态:** 已接受并实施；公共启用仍受环境限制
**日期:** 2026-07-31

## 背景

生产版本v0.0增加了论文级别的讨论，这是公开的用户生成内容。一个没有举报、屏蔽、管理、速率限制、条款接受、删除和响应流程的评论功能将导致一个不安全且操作上不支持的发布。

## 决定

仅提供公开、扁平、论文级别的评论。访客可以阅读已发布的评论；具有处理和接受条款及社区指南的活跃认证用户可以创建评论。评论是标准化的纯文本，有严格的标量/字节/URL限制，按最新顺序排列，不包含HTML、附件、回复、反应、投票、实时更新或匿名发布。

创建过程使用确定性验证和垃圾邮件规则，账户/IP-设备速率限制，账户状态检查，以及一个可选的提供者中立的服务器端管理适配器。实现的远程接口是一个经过审查的出口的单个受限制的HTTPS JSON调用，它不是移动SDK或新的Pakperk服务。可疑或模型不确定的结果将被保留以供审查或暂时拒绝，而不是自动发布。用户可以编辑/删除自己的评论，举报评论或用户，并单独屏蔽其他作者。管理员可以审查举报，隐藏/恢复评论，并通过经过审计的工具暂停/恢复账户。一个全局功能标志可以禁用新评论，而不禁用阅读。

## 后果

- 评论需要标准化的评论、举报、屏蔽和管理事件表；客户端创建使用稳定的请求ID以实现幂等性。
- 发布需要在Pakperk中显式记录社区政策接受记录，而不仅仅是身份提供者同意屏幕。
- 在启用公共标志之前，产品必须提供清晰的公开内容披露、支持联系、举报用户体验、账户删除和报告响应的所有权。
- 初始管理界面可能是认证的管理员CLI，但它必须审计行为者和行为，并避免除显式检查外的内容打印。

## 安全和操作影响

- 评论内容、举报详情、身份和管理元数据是敏感的操作数据：从遥测中删除它们，并严格限制对它们的访问。
- 服务器端验证是权威的；客户端计数器和过滤器仅作为便利功能。渲染的链接需要安全解析和外部导航保护。
- 幂等性和所有者受限的SQL防止重复重试和跨账户的编辑/删除访问。私有资源失败应避免在适当情况下泄露存在性。
- 发布受经过测试的管理操作、实时支持路线、条款/社区页面、速率限制、保留/删除策略和定义的事件/报告响应所有者的限制。

## 实现结果

第5阶段在现有的Rust后端和PostgreSQL数据库中实现了扁平评论、举报、屏蔽、接受、共享限制、规则管理、适配器和管理审计模型。API注册和新发布使用单独的部署标志。Flutter客户端保持有限的个性化页面、账户范围的草稿和持久化的屏蔽，这些功能在账户和认证纪元的写入屏障后；草稿永远不会进入自动出站。`pakperk-admin`提供明确的检查/操作命令，带有可追溯的审计记录和无内容队列指标。它仅授权最近的OIDC `auth_time`映射到一个活跃的本地账户，其UUID在受保护的操作员允许列表中；普通认证账户不能调用管理操作。

该仓库现在实现了该ADR所需的内置/网页账户删除、保留和恢复重放机制、托管的支持/法律路线、遥测管道和警报/运行手册合同。发布门未被削弱：公共创建在这些机制针对目标环境进行测试并获得最终法律、管理、隐私和存储政策审查批准其证据之前仍保持关闭。
