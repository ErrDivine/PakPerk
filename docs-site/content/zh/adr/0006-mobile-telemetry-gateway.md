# ADR 0006：执行 schema 校验的移动端遥测网关

- 状态：已接受
- 日期：2026-07-31

## 背景

移动版发布证据需要聚合的运营信号，但原生应用无法安全持有 OTLP 后端凭据，
也不得发送账户、设备/会话、论文、内容、令牌、原始异常或堆栈数据。
如果允许任意 OTLP 属性，隐私行为就会取决于每一个调用位置，
并可能绕过后端既定的脱敏要求。

## 决策

移动端只向当前环境中精确的 `/v1/logs` 端点发送尽力而为、未经认证的
HTTPS POST 请求。专用 Rust 网关只接受一种有界的 JSON/OTLP 载荷结构，
拒绝未知事件名称、未知属性和敏感键，执行每个请求 16 KiB 的上限以及媒体类型、
方法和路径限制，并将接受的记录导出到集群内的 Collector。应用设置两秒截止时间，
最多允许两个进行中的发送，并且不使用持久队列、重试、Cookie、Authorization 请求头或标识符。
发送失败时直接丢弃遥测，不改变任何产品行为。

Ingress 提供按客户端计算的粗粒度连接数和限流。网关的封闭 schema 构成隐私边界。
作为第二层防护，下游 Collector 仅在服务、环境、作用域和事件名称与该模式完全一致时
保留日志正文；其余所有直接 OTLP 日志正文都会替换为固定标记。
无崩溃发布证据采用经过外部审核的聚合分发/商店分母，绝不为此虚构稳定标识符。

在应用故障跨越框架、平台、Zone 或启动诊断边界之前，客户端会把原始异常和
Dart 堆栈替换为一个有界错误类别及 `StackTrace.empty`。如果此前没有处理程序接收
该故障，替换后的故障仍保持未捕获状态，从而不会掩盖崩溃行为；原始回调参数绝不会
交回引擎的后备日志记录器。

Plan 02 的队列政策观测也使用同一个封闭边界。客户端只能上报以下项目的粗粒度时长桶：
待处理保存/导入的存在时长、从保存到推荐抑制的延迟、从最终确认到服务端解除锁定的延迟，
以及 Library 中最早待同步队列（outbox）项目的存在时长。推荐发布被拒与 Library 冲突事件使用封闭的
原因/边界枚举。源时间戳、账户/认证作用域、待同步队列（outbox）操作、导入操作、论文身份和服务器响应
身份都只保留在设备上。时间戳或作用域缺失时，只产生 `unknown` 或不生成计时样本；
绝不会根据原始时间戳属性重建。这些是必要的队列和产品状态观测；关闭个性化功能时，
它们不会借机启用交互或个性化数据收集。

## 后果

- 移动应用包不含可观测性凭据，直接上游 OTLP 坐标保持私密。
- 新增事件或属性词汇必须先完成代码、测试、隐私披露和网关审核，才能逐步发布。
- 离线或容量饱和期间会有意丢失遥测，因此这些指标只是运营抽样，并非完整的行为分析。
- 源码测试可以证明校验和脱敏机制，但真实保留行为、入口行为、具有代表性的崩溃窗口和应用商店披露信息仍须作为外部发布证据。
