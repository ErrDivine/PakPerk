# ADR 0001: OIDC 和 Keycloak 参考部署

**状态:** 已接受 —— 账户验证和删除管理已实现  
**日期:** 2,026-07-31

## 背景

Pakperk 必须保留访客阅读功能，同时允许用户拥有同步保存并参与受管理的公开评论。应用程序不得收集或存储密码。原生客户端还需要安全的令牌生命周期，账户删除必须撤销并移除上游身份，在参考部署中实现。

## 决定

Pakperk 是一个 OpenID Connect 原生客户端和资源服务器。移动端使用系统浏览器中的授权码流程（PKCE S256）。API 使用 OIDC 发现和 JWKS 验证令牌，包括签名、允许的算法、颁发者、受众、过期/未过期前、时钟偏移和必需的主体。

Keycloak 是本地、测试和默认的自托管生产参考提供者。API 授权保持提供者中立：验证的 `(颁发者, 主体)` 值被事务性地映射到本地用户，破坏性提供者操作由 `IdentityAdmin` 适配器处理。Keycloak 是该适配器的参考实现目标；一个无操作适配器仅限于显式不完整的测试/本地流程。

只有刷新令牌和最小会话元数据被持久化在平台安全存储中。访问令牌在内存中保留（如果可行）。Pakperk 默认不将电子邮件复制到其数据库中。

## 实现状态

提供者中立的验证器、可发布的认证就绪运行时、本地账户映射、原生 AppAuth 客户端、平台安全令牌存储、参考 Keycloak 域和可选的 `GET`/`PATCH /v1/me` 接口已集成在 `ACCOUNTS_ENABLED` 下。访客纸张路由与 OIDC 就绪无关。第三阶段验证报告记录了成功的仓库、原生、实时 PostgreSQL 和真实 Keycloak/Mailpit 接受运行。

提供者中立的 identity-admin 适配器现在有一个有界的 Keycloak 实现，仅由专用的删除工作线程加载。启动时获取客户端凭证令牌，并通过非破坏性保留用户读取证明其确切的 `manage-users` 授权；重定向、错误状态/形状、过大响应和缺少权限会关闭失败。会话撤销和身份删除是租约删除状态机中的幂等步骤。凭证是仅所有者文件，提供者坐标在独立签名的恢复账本中加密。生产启用仍需要执行的域授权、密钥轮换、警报、独立备份拓扑和恢复重放。

## 后果

- 用户可以在没有账户的情况下浏览和阅读；保存、评论、报告、阻止和账户设置需要经过认证的本地用户。
- 移动端必须实现安全存储、单次刷新、重新认证、注销清理和幂等性感知的重试。
- 后端配置必须包括颁发者、受众、允许的算法、发现/JWKS 超时和在生产中启用账户删除时的功能性 identity-admin 配置。
- Pakperk 获得一个与提供者显示数据无关的本地用户记录和公开句柄，避免基于客户端提供的配置文件字段的授权。

## 安全和操作影响

- 原生客户端是公开的：不包含嵌入式客户端密钥，重定向/注销后 URI 必须精确。
- 令牌内容、授权头、OIDC 主体标识符和电子邮件必须从日志、遥测、崩溃报告和本地通用存储中删除。
- 当必需的验证元数据不可用时，验证会关闭失败；未签名的令牌和令牌选择的算法永远不会被接受。
- Keycloak 必须强制执行电子邮件验证、暴力保护、密码恢复、短生命周期访问令牌和受保护的刷新令牌轮换/会话策略。
- 账户删除会立即禁用本地账户、撤销上游会话，然后执行幂等的异步删除。生产启动必须拒绝在没有工作 admin 适配器的情况下启用删除功能。
