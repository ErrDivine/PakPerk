# ADR 0002：Drift 本地数据库

**状态：** 已接受——已在阶段 2 实现
**日期：** 2026-07-31
**实现日期：** 2026-07-31

## 背景

演示版将 JSON 数据块存储在 SharedPreferences 中。生产环境则需要容量有界且可查询的多页 Feed 缓存、对已保存论文的驻留保护、评论缓存、草稿、按账户隔离的状态、schema 迁移、事务，以及持久化的待同步队列（outbox）。这些需求无法作为一组偏好设置数据块安全管理。

## 决策

使用基于 SQLite 的 Drift 作为移动端内容数据库。它负责关系型公共缓存数据、已保存论文的投影数据、评论缓存、草稿、缓存元数据以及用于重试的待同步队列（outbox）。SharedPreferences 仅用于存储少量标量型偏好设置和选定的恢复元数据。身份认证令牌不存储在 Drift 中，而是继续保存在平台安全存储中。

Feed 仓库继续采用缓存优先策略，并在后台重新验证期间允许返回陈旧缓存。Drift 的 schema 迁移均显式定义；公共数据可以在退出登录后继续保留；在退出登录和删除账户时，账户自有数据行及待同步队列（outbox）记录会被清除，或严格限定在对应账户的作用域内。

## 已实现的结构

生产数据库使用稳定的文件名 `pakperk_content.sqlite`，当前 schema 版本为 10。数据库启用了外键并采用 WAL 模式。schema 包含：

- 规范化的论文表、Feed 查询表和有序 Feed 成员关系表；
- 与处理代次和 arXiv 版本绑定的处理状态、Introduction、Connections 及匿名聊天缓存；
- 容量有界的评论页缓存；
- 按账户隔离的五状态 Library 表，以及自定义列表/标签成员关系、草稿、待同步队列（outbox）、同步状态和缓存元数据表；
- 与代次绑定的规范化文档、Passport、视觉和语义响应缓存，以及仅记录位置的阅读检查点；
- 按账户隔离的注释、保留的笔记冲突版本、证据卡片、记忆项、研究待同步队列（outbox）/同步状态和版本差异缓存条目。所有 Plan 03 功能仍受默认关闭的构建开关和服务器开关控制。

Feed 数据行以一个不透明且带版本的标识为键，其中包含确切的类别和条数上限。第一页验证器随对应查询一同存储，追加游标分页时则保留该验证器。论文元数据只会按 arXiv 版本和来源更新时间单调向前更新。较新的论文版本会在同一事务中清除派生数据行；处理代次发生变化时，则会阻止迟到的 Introduction、Connections 或聊天响应越过重试边界写入。

一次性旧版导入器使用常规模型解码器解析现有的 Feed、论文、处理状态、Introduction、Connections 和聊天 JSON 数据块，在同一事务中导入并验证符合条件的数据行，并且只在验证成功后删除批量偏好设置键。只有同时满足以下条件时，导入器才接受派生记录：单独缓存的论文能够证明完全一致的 arXiv 版本；JSON 明确携带正数代次；该代次对应的处理状态行已先完成导入。对于聊天数据，还必须有显式的会话/论文/arXiv 封装，并且它既要匹配来自 Feed 或恢复路由的确切阅读器键，也要匹配导入器构造时已经存在的匿名会话。导入器绝不会生成或重新采样身份标识来标注旧聊天；因此，导入器会在作用域校验失败时默认拒绝确实不带作用域信息的 v1 派生数据块和聊天数据块，而不会借用较新的溯源信息。只有当捕获的完整批量快照和已导入的聊天会话均保持不变时，才会提交迁移完成标记；清理时还会在删除前再次比较每个键。无效、类型错误或未绑定的数据行只会计数，不会记录其内容。失败或发生竞态的事务会保留源偏好设置，并且不会阻塞启动。在严格的全文策略下，公共元数据会被遮蔽，所有旧版派生记录都会按策略丢弃。

淘汰过程依次处理过期评论、陈旧且非活跃的 Feed 成员关系，并依据 LRU/TTL 淘汰未固定的论文；最后仅在字节容量存在压力时，淘汰已过期或最旧且不受保护的派生代次簇。它会保护当前活跃的阅读器窗口、已恢复的论文路由和聊天、Library 中已固定的论文、草稿，以及待同步队列（outbox）中待处理记录的所有权关系。滑动操作期间的维护不会执行数据库收缩，但会强制遵守元数据行数和 SQLite 当前占用字节数的上限。物理分配量包括主数据库文件、WAL 文件和共享内存文件；检查点操作和 `VACUUM` 仅在生命周期处于非交互状态时运行。

`FeedPrefetchCoordinator` 与界面分离，只接收 Feed 页面远程接口和 Drift 持久化能力。其默认值集中定义：远程页面每页 30 行，在剩余 10 项时触发；可读窗口在当前位置之前保留 2 项、之后保留 6 项；前方持久化 60 行；元数据上限为 500 行；数据库容量上限为 64 MiB；元数据 TTL 为 7 天。每个查询内的合并并发机制、快照失效判定、有界重试和游标循环终止机制共同保证推测性预取工作的一致性。收窄后的远程接口使“不得触发论文准备”成为结构边界，而不只是调用方需要遵守的约定。

## 后果

- 应用包含数据库生成代码、迁移测试、数据库生命周期管理、有界缓存淘汰机制，以及从旧版偏好设置迁移的逻辑。
- Feed 缓存条目能够区分查询、类别和游标，不再只是单个首页 JSON 值。
- 数据库 schema 会在离线时将幂等的保存/取消保存操作持久化到待同步队列（outbox）中，其受保护的同步行为由阶段 4 负责。公共评论草稿始终与待同步队列（outbox）分离，绝不会自动发布。
- 在数据模型变得可查询且支持事务的同时，现有的缓存优先 UI 行为得以保留。

## 安全与运维影响

- SQLite 不包含访问令牌、刷新令牌、原始授权材料或账户凭据。
- 账户自有表在结构上单独划分，以便退出登录或切换账户时进行清理，并支持后续删除；公共论文元数据可以继续离线使用。
- 私有研究正文以普通 SQLite 文本形式存储。本 ADR 不声称提供应用层数据库加密：当前的本地安全边界由操作系统应用沙盒、设备访问控制、平台文件保护，以及备份排除或禁用机制共同构成。暂缓引入 SQLCipher，直至经过审查的威胁模型明确密钥所有权、迁移、备份还原/故障恢复、轮换和清理方案。
- 缓存大小、TTL、LRU 淘汰、已保存论文的驻留保护，以及生命周期安全的物理压缩均有专项指标和测试。
- 数据库迁移均显式定义，并使用完整的历史数据库模式测试夹具完成截至版本 10 的迁移测试。
  在版本 3 迁移期间，会丢弃不含代次信息且可重建的派生数据块，而不会将其重新标记为当前数据。后续迁移依次添加 Library 同步状态、与账户绑定的评论缓存/草稿和屏蔽关系，移除已停用的回复列，添加 Plan 02 的 Library/搜索/阅读 Feed 投影，再添加 Plan 03 的文档缓存和私有研究缓存，同时不削弱此前建立的边界。
