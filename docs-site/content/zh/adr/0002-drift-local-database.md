# ADR 0002: 漂移本地数据库

**状态:** 已接受 —— 实现于第二阶段
**日期:** 2026-07-31
**实现日期:** 2026-07-31

## 背景

演示将JSON二进制大对象存储在SharedPreferences中。生产环境需要有限的、可查询的多页流缓存、保存的论文固定、评论缓存、草稿、账户范围的状态、模式迁移、事务以及持久化的同步出站队列。这些无法安全地作为一组偏好二进制对象来管理。

## 决定

使用Drift替代SQLite作为移动内容数据库。它负责关系型公共缓存数据、保存的论文投影、评论缓存、草稿、缓存元数据以及重试出站队列。SharedPreferences仅用于存储小型标量偏好和选定的恢复元数据。认证令牌不存储在Drift中；它们继续保留在平台安全存储中。

流仓库保持以缓存优先和过期时重新验证的方式。Drift模式迁移是显式的，公共数据可能在退出登录后保留，账户拥有的行和出站队列记录在退出登录和账户删除时会被清除或限制。

## 实现结构

生产数据库使用稳定的`pakperk_content.sqlite`文件名，当前模式版本为6。外键已启用，数据库使用WAL模式。模式包含：

- 规范化的论文、流查询和有序流成员表；
- 基于生成版本和arXiv版本的处理、引言、连接和匿名聊天缓存；
- 有限的评论页缓存；以及
- 账户范围的图书馆、草稿、出站队列、同步状态和缓存元数据表。第四阶段仅在功能门控后激活图书馆子集；评论行为保持禁用。

流行由一个不透明、版本化的标识符键，包括确切的类别和限制。第一个页面验证器与该查询一起存储，而光标页追加会保留它。论文元数据按arXiv版本和源更新时间单调递增。较新的论文版本在同一事务中清除派生行，处理生成版本的变化防止引言、连接或聊天响应跨越重试边界。

一次性遗留导入器使用普通模型解码器解析现有的流、论文、处理、引言、连接和聊天二进制大对象，导入并验证接受的行在一个事务中，并在验证成功后仅删除批量偏好键。只有当个别缓存的论文证明了确切的arXiv版本、JSON显式携带了正生成、并且该生成对应的处理行首先被导入时，派生记录才被接受。聊天还需要一个显式的会话、论文和arXiv信封，与确切的流/恢复读取器键和导入器构建时存在的匿名会话匹配。它从不生成或重新采样身份来标记旧聊天，因此真实的未限定v1派生/聊天二进制大对象会失败关闭而不是借用较新的来源。标记仅在完整的捕获批量快照和导入的聊天会话保持不变时提交，并在删除前再次比较每个键。无效、类型错误和未绑定的行会统计而不记录其内容。失败或竞争的事务会保留源偏好并不会阻止启动。在严格的全文策略下，公共元数据会被屏蔽，所有派生的遗留记录都会被策略丢弃。

驱逐会应用评论过期、过期的非活跃流成员、未固定论文LRU/TTL，以及在字节压力下过期或最旧的未保护派生生成簇。它保护活跃的读取窗口、恢复的论文路线和聊天、图书馆固定、草稿和待出站所有权。滑动时间维护在不进行真空操作的情况下强制元数据行和活跃SQLite字节边界。物理分配包括主数据库、WAL和共享内存文件；检查点和`VACUUM`仅在非交互生命周期状态期间运行。

`FeedPrefetchCoordinator`与屏幕分离，仅接收流页远程接口和Drift持久化能力。其默认值是集中的（30行页、触发剩余10行、可读窗口中2个在后、6个在前、60个持久行在前、500个元数据行、64 MiB和7天的元数据TTL）。查询本地的单次飞行、快照过时、有限重试和光标循环终止保持推测工作的一致性。狭窄的远程接口使无准备边界成为结构而非调用约定。

## 后果

- 应用生成了数据库代码、迁移测试、数据库生命周期管理、有限缓存驱逐和从遗留偏好迁移。
- 流缓存条目变为查询/类别/光标感知，而不是单一的初始页JSON值。
- 模式在离线时在出站队列中持久化幂等的保存/取消保存操作，第四阶段拥有其受保护的同步行为。公共评论草稿保持与出站队列不同，永远不会自动发布。
- 现有的以缓存优先的UI行为被保留，而数据模型变得可查询和事务化。

## 安全和运营影响

- SQLite中不包含访问令牌、刷新令牌、原始授权材料或账户凭证。
- 账户拥有的表在退出登录/账户切换清理和后续删除时结构上分离；公共论文元数据可以离线保持可用。
- 缓存大小、TTL、LRU驱逐、保存论文固定和生命周期安全的物理压缩有重点的指标和测试。
- 迁移是显式且从完整的原始模式快照测试到版本6。
  在版本3迁移期间，可重建的预生成派生二进制大对象会被丢弃而不是重新标记为当前。后续迁移添加了同步图书馆状态、账户绑定的评论缓存/草稿和块，并删除了沉睡的回复列而不削弱之前的边界。
