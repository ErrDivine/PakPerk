# ADR 0007：将公开发现与已认证阅读信息流分离

**状态：** 已接受并实现，受默认关闭的运行时分阶段发布门禁控制
**日期：** 2026-08-19
**历史基线：** `cde04d1b2c49c0c8673559fb8d7816cc604536d9`
记录了本 ADR 开篇背景中所述的实现前行为。

## 背景

Pakperk 当前将 `GET /v1/feed` 作为匿名的按时间顺序/类别排列的信息流公开。
该路由始终注册，使用不透明的公开信息流游标，并返回
`Cache-Control: public, max-age=60, stale-while-revalidate=300`。
已登录客户端还拥有账户所属的 `to_read` 集合，支持幂等变更、按用户维护的修订号、
墓碑记录和私有同步路由。

让公开路由感知账户，会把彼此不兼容的权威边界和缓存边界混在一起。
这可能使私有队列决策受制于公开缓存，破坏访客和旧客户端的行为，
并导致无法明确判断：账户队列为空或不可用时，是否有权提供推荐。

## 决定

Pakperk 将保留两种不同的流语义：

- `GET /v1/feed` 继续作为公开发现信息流。其现有线协议结构、匿名可用性、公开缓存策略、游标用途，以及作为按时间顺序推荐来源的角色均保持兼容。
- `GET /v1/me/reading-feed` 作为已认证、账户范围的信息流。只有启用其默认关闭的分阶段发布门禁后，它才会成为兼容的已登录客户端所使用的规范 Read 信息流。所有响应和错误均为私有且不可存储。

认证路由从一个提交的数据库快照中决定其模式：

```text
active To Read count > 0
    => mode = to_read
    => every returned item is an active row for that account

active To Read count = 0
    => mode = recommendations
    => recommendations may be returned
```
  
数据库、认证、修订号或同步状态不确定，并不等于队列为空。
无法证明决策成立时，该路由会在失败时默认拒绝，而不是返回推荐。

客户端还会应用一道本地门禁。只有在以下条件全部成立时，才可发布推荐响应：
账户和认证纪元仍然匹配；响应声明 `mode=recommendations`；本地权威状态仍为
`serverConfirmedEmpty`；并且请求开始后没有出现待处理保存、移除状态转换、导入意图、
本地活动记录或同步重置冲突。否则丢弃响应，并重新执行仲裁。

已认证游标具有专用的加密用途，并绑定到本地账户、信息流模式、Library 修订号、
查询、页面大小策略、密钥纪元和过期时间。Library 修订号变化后，继续分页所用的游标
即告失效；服务器返回 `409 READING_FEED_CURSOR_STALE`，客户端从第一页重新开始。

队列政策继续位于与传输无关的推荐来源之上。首个来源可以调整当前按时间顺序的
论文查询，但推荐器永远无权决定自身是否可以运行。

该功能仍位于现有 Rust/Axum API 与 PostgreSQL 模块化单体中。
它不会新增服务、数据库、消息代理、工作进程路径，也不会让移动端连接 arXiv。
保存、列出、导入或纵向预取元数据绝不会启动论文准备。

完整的线协议与状态机契约记录在
[已认证阅读信息流](../reading-feed.md)、[手动论文搜索与导入](../paper-import.md)和
[To Read First 部署边界](../deployment-boundaries.md)中。

## 后果

- 访客及尚未采用已认证路由的客户端继续保持现有的公开信息流行为。
- 只要受支持的旧客户端仍可仅使用公开信息流，就不能认为已登录用户的队列优先分阶段发布已得到强制执行。严格执行前必须确定最低版本或等效的发布政策。
- API 需要与快照一致的队列决策、绑定账户及修订号的游标、推荐排除、稳定错误、私有缓存响应头和不变量测试。
- 移动端必须把队列权威状态建模为状态，而不能只使用 `isEmpty`；权威状态未知时应禁止获取或渲染推荐，并在账户或认证变化后取消迟到的工作。
- 公开论文摘要可以继续使用普通元数据缓存，但缓存的推荐页面永远不能作为账户队列为空的持久证据。

## 安全和运营影响

- 个性化响应使用 `Cache-Control: private, no-store` 和 `Vary: Authorization`；正文、实体标签、游标、日志及指标中都不包含可读的用户标识符。
- 队列权威故障返回类型明确、可重试的错误；对于已登录客户端，绝不会静默降级为公开发现。
- 所有新路由和严格执行开关都各自默认关闭，并已校验其对现有账户和 Library 门禁的依赖关系。
- 回滚会禁用已认证功能并恢复旧客户端路径；不会修改或重新解释公开信息流或现有 Library 线协议技术契约。
