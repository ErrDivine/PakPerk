# ADR 0003: 有状态壳层路由

**状态：** 已接受 — 核心决策已于第 1 阶段实现；之后又增加了 Library 分支
**日期：** 2026-07-31

## 背景

演示版的自定义 Navigator 原本包含信息流根页面和论文路由。第 1 阶段新增了 Read
和 You 两个目的地；二者都必须保留各自的导航栈与恢复状态。深层链接必须
在 Read 中打开论文，同时不得丢弃其他目的地保留的状态；论文阅读器的横向
阶段则仍是界面内部状态，而不是路由。

## 决策

第 1 阶段决定采用 `go_router`，通过
`StatefulShellRoute.indexedStack` 建立 Read 和 You 两个分支。壳层负责
常驻的主导航，并为每个分支使用独立导航器。论文详情路由归属 Read；账户路由
以及当时使用的个人论文库路由归属 You。根级论文聊天和评论路由作为
模态/全屏路由显示在壳层之上。

## 当前实现

后续的 Library 功能在不改变核心决策的前提下扩展了这个索引栈。
当前可见的主导航目的地是 Read、Library 和 You，每个目的地都有独立的有状态
分支导航器。窄屏布局使用底部导航栏，宽屏布局使用侧边导航栏。Read 包含论文路由，
Library 的规范路径是 `/library`；账户、设置及账户专属管理路由仍归属 You。
旧的应用内路径 `/you/library` 作为兼容入口重定向至 `/library`。根级论文聊天和评论路由
仍由根导航器承载，并以全屏对话页形式显示在壳层之上。

用于持久化的分支索引刻意保留原有的 `Read = 0, You = 1` 映射，同时规定
`Library = 2`；但壳层在界面上的显示顺序是 Read、Library、You。将用于持久化的
分支标识与显示顺序分开，可以避免恢复旧版本保存的 You 会话时误将 Library 打开。

Read 根页面在自己的分支内保留了现有的、基于页面的关联论文导航器。这样可以在既定的
恢复策略与容量边界内，精确保留演示版的论文跳转轨迹、阅读阶段、滚动位置和系统返回行为；
同时由
`go_router` 负责正式应用的壳层与公开路由。页面恢复 ID 保持稳定；每次新打开公开论文
或 arXiv 入口时，系统都会分配一个全新的阅读器状态键，而不会复用此前阅读界面中的
阶段状态。普通公开链接从 Abstract 开始；经验证的内部“从此论文生成关系图”操作可以
显式从 Connections 开始。论文阅读器中的 Abstract、Introduction 和 Connections 阶段仍属于
阅读器内部交互，并继续遵守现有边界：内容准备只会在规定的阶段切换正式提交后触发。

## 后果

- 切换主导航目的地时，系统会保留滚动位置、嵌套导航状态和选中状态，而不会重建这些
  目的地。
- 路由支持 `/read`、`/read/paper/:paperId`、公共 `/p/:paperId` 和
  `/arxiv/:arxivId` 入口、`/read/paper/:paperId/chat`、
  `/read/paper/:paperId/comments`、`/library`、兼容性重定向
  `/you/library`、`/you` 以及设置和账户相关目的地，但聊天或评论不会因此成为额外的
  主导航目的地。
- 从 Library 打开已保存论文时，系统会有意在保留的 Library 分支之上压入一个 Read
  路由，因此常规返回操作会回到此前那个确切的已保存论文列表路由。
- 路由器、深层链接、状态恢复、返回导航和功能开关行为都需要有针对性的 Widget 测试
  和集成测试。
- 功能被禁用的目的地必须通过一致的路由转到说明页面或可用的访客界面，绝不能留下
  点击后无响应的导航控件。
- 嵌套的 Read 导航器是一处刻意保留的兼容衔接层。只有当迁移方案能够证明
  Connections、返回导航和滚动位置恢复行为完全一致后，才应重新评估这一设计。

## 安全和运营影响

- 深层链接本身绝不提供授权依据；受保护的操作仍必须依据服务端解析出的主体身份。
- 路由参数被视为不可信的标识符，并在加载数据前进行验证。
- 恢复状态数据不得包含令牌、非公开的个人资料数据、评论正文或其他敏感信息。
- 有状态分支在整个生命周期中的内存占用，需要在性能较低的设备上进行观测，并测试
  缓存边界。
