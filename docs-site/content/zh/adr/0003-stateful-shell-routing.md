# ADR 0003: 状态路由

**状态:** 已接受 —— 实现于第一阶段
**日期:** 2026-07-31

## 背景

演示中的自定义 Navigator 有一个 feed 根节点和 paper 路由。生产环境添加了 Read 目标和 You 目标，每个目标都必须保留自己的栈和恢复状态。深度链接必须打开 paper 而不重置所选目标，而 paper-reader 水平阶段保持本地 UI 状态，而不是路由。

## 决定

采用 `go_router` 使用 `StatefulShellRoute.indexedStack` 实现 Read 和 You 分支。壳层拥有持久的底部导航和独立的分支导航器。Paper 详情路由属于 Read；账户和图书馆路由属于 You。根聊天和评论界面作为模态/全屏路由覆盖壳层。

Read 根节点保留其分支内现有的基于页面的链接 paper 导航器。这刻意保留了演示中精确的 paper 追踪、阶段、滚动和系统返回恢复，而 `go_router` 拥有生产壳层和公共路由。路由恢复 ID 是稳定的，每个公共 paper/arXiv 调用都会获得一个新鲜的 reader key，使其从 Abstract 开始，而不是重用之前的屏幕内阶段。Paper 阅读器的 Abstract、Introduction 和 Connections 阶段保持本地交互，其现有的提交过渡准备边界不变。

## 后果

- 切换标签页时保留滚动位置、嵌套导航和选中状态，而不是重建目标。
- 路由支持 `/read`、`/read/paper/:paperId`、公共 `/p/:paperId` 和 `/arxiv/:arxivId` 入口点、`/read/paper/:paperId/comments`、`/you`、`/you/library` 以及设置/账户目标，而无需将评论作为第三个主要标签页。
- 路由器、深度链接、恢复、返回导航和功能标志行为需要重点 widget 和集成测试。
- 禁用的目标必须路由到解释或可用的访客界面，绝不能留下死导航控件。
- 嵌套的 Read 导航器是一个有意的兼容性接口。只有在迁移可以证明相同连接/返回和滚动恢复行为后，才应重新考虑。

## 安全和运营影响

- 深度链接从不提供权威信息；受保护的操作仍需要解析后的服务器主体。
- 路由参数被视为不可信的标识符，在加载数据前进行验证。
- 恢复数据不得包含令牌、私有个人资料数据、评论正文或其他敏感材料。
- 状态分支的生命周期需要在低端设备上进行内存观察和缓存边界测试。
