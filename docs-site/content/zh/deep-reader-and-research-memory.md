# Deep Reader 与研究记忆

Pakperk v0.2 在不改变队列优先权限模型的前提下深化阅读体验。有效的 To Read 队列仍是自动跳转到下一篇论文的唯一来源。阅读进度、检查点、文档末尾、标注、证据卡片、明确的 Search/Connections/Memory 分支和记忆复习都不能改变 Library 状态，除非用户明确执行 Library 变更操作。

本文档是仓库技术契约，并不表示 Plan 03 的每项发布门禁都已通过。分阶段发布所需的受保护证据定义在 [Deep Reader 发布运行手册](runbooks/deep-reader-rollout.md)及其[评估状态](evaluations/deep-reader-v0.2.md)中。

## 阅读器与文档契约

规范化文档模型使用绑定处理代次的稳定块键、来源定位器、章节祖先关系、页面映射，以及行内引用/术语/符号范围。生成的 Passport 字段、Assistant 论断、定义、视觉对象、标注、证据卡片和版本差异必须保留可解析的来源记录。产品契约要求用户始终只需一次操作即可打开原始来源。版本历史和每个差异项目现在都会显示所保留的确切 arXiv 来源版本；对象 ID 绝不被当作公开链接。只有保留的解析器定位器可信时，视觉对象或差异操作才会打开确切的 PDF 页面；否则会回退到所保留的确切来源版本。

Skim、Read 和 Inspect 是同一份规范化来源的不同呈现模式，而不是不同文档。选择模式不能改变 Library 状态。如果解析或来源记录存在不确定性，界面会显示这种不确定性，或回退到元数据/来源访问。界面不得虚构重建内容。

GROBID 仍是生产解析器基线。适配器选择和来源记录遵循 [ADR 0008](adr/0008-document-ingestion-adapter.md)。Docling 只是一项实验；如果没有带版本的基准、资源、回退、重新处理和回滚证据，其功能开关并不构成替换基线的许可。

仓库目前已在默认关闭的控制项后实现 Plan 03：

- 迁移 19 记录并强制执行经过批准的准备触发方式；
- 迁移 20 存储与解析器无关的处理代际、章节树、块、行内范围、图、表、公式、术语、定义和来源定位器，同时继续发布旧版 Introduction 能力；
- 迁移 21 增加共享来源信息、Passport 字段和字段反馈、链接来源的语义范围、有界 Assistant 线程/消息，以及绑定主体且针对具体证据的 Assistant 反馈评估；
- 迁移 22 增加主体范围的标注、保留的备注冲突、重新锚定历史、证据卡片、仅含位置的检查点、记忆项目和幂等的研究产物操作流；并且
- 迁移 23 存储有界的代际间差异清单和结构化差异项目；并且
- 迁移 24 增加原子化的主体范围标注归档导入、不含内容的导入幂等性，以及无损保留的冲突解决结果。

在移动端，横向阶段仍为 Abstract、Introduction + Assistant 和 Connections。Skim、Read 和 Inspect 是这些阶段内部限定论文范围的模式。阅读器沿用现有、限定账户/认证纪元范围的阅读信息流权限来自动导航，在文档末尾自然停止；当文本选择或表格平移拥有手势时，会阻止横向翻页；它可以恢复位置，但不会把检查点视为 Library 状态。缓存的文档行和私有研究行同时限定处理代次与账户范围；迟到的响应和重放的待同步队列（outbox）工作会在发布前被隔离。

仅当论文已声明当前就绪的 Passport 时，Abstract 才可以发起公开且认证可选的 Passport 读取；它绝不会请求准备。用户确认进入 Introduction 后，可见的阅读器可以使用有界、只发 GET 的状态观察器，观察后续视觉对象、术语、分面和 Passport 能力，同时已准备的文本仍可阅读。Skim 最多渲染八个已加载块，从不分页，也不报告真正的文档末尾。Read 和 Inspect 保持有界、仅活跃时执行的分页，显示明确的章节停止点与文档末尾停止点，并说明没有发生 Library 状态转换。Read 还会把一个 48 点、适配大字体的 Assistant 输入框固定在文档滚动区域之外；明确且有界的问题只会交接给指定证据范围的面板一次，而该面板会在键盘上方保留自己的输入框。语义提示默认采用可恢复的 `Key` 密度，另提供 `Off` 与 `Detailed`；提示使用颜色以外的区分方式，并依次打开当前论文、被引论文、术语表，再打开清楚标记为生成内容的定义，而不会根据原始选择内容自行合成。

研究记忆也可以通过归账户所有的明确目的地 `You -> Memory` 访问。它的有界分页到期队列可以跨越多篇论文，但不会成为另一条阅读信息流。今天晚些时候、明天、一周后、自定义暂缓和归档操作只更新记忆项目；打开来源论文会保留 Memory 返回来源，且不会写入 Library 历史或队列成员关系。权威跨设备快照中不存在的干净缓存行会被移除，而尚未同步的本地写入仍可恢复。

在 Plan 03 的多个发布边界上，源代码实施会刻意在失败时拒绝。GROBID 会规范化图注、表格网格/纯文本回退和带有绑定处理代次定位器的公式来源。worker 只接受经操作员准确审查的 PNG 关联；它会在不信任解析器路径的情况下预检文件，解码并重新编码以去除辅助元数据，再原子发布一组绑定清单哈希、限定处理代次范围的小/中/大版本。已认证端点会先重新验证策略、能力、对象、处理代次、图片集范围、清单与文件哈希、媒体类型、尺寸、宽高比和大小，再提供所请求的版本。移动端会验证响应绑定，并按版本为有界缓存设置键。来源缺失或无效时，系统会清除陈旧资源元数据并保留标题/准确页面回退。公式采用忠于确切来源、不会修复内容的受维护渲染方式：SmartMath 的清理/输入修复已禁用；格式错误的 LaTeX 或不受支持的 MathML 会回退为可选择的确切来源。worker 绝不会推断 PDF 裁剪；在存在经过审查的持久草稿架构前，生成无障碍说明的任务会以终态失败。视觉对象启用仍受阻于受保护的来源关联、版权、精度、无障碍、真实流水线和签名设备证据。

移动端文档客户端使用有界分页、仅在 Inspect 中惰性加载视觉对象、取消隔离，以及明确的 2,000 块设备预算技术契约；但尚无受保护的实体设备运行提供所需测量结果。有界 JSON 研究导出和原子标注导入现在可以在数据库/移动技术契约测试中往返还原标注、选择器、保留的冲突、合并后的冲突正文和确切的重新锚定历史。每个受支持的差异对象都会依据所保留的确切论文处理代次来解析：存在可信定位器时打开匹配的 PDF 页面，否则回退到所保留的确切来源版本。签名设备导入/重排/冲突、差异导航和大文档结果仍为 `not_ready`；仓库测试和暗置界面不能替代受保护的执行结果。

## 证据优先的生成

每项生成产物都会记录论文、处理代次、来源块/对象、解析器/架构版本，以及适用时的模型/提示版本。只有在引用的每个证据 ID 都存在于允许的检索集合中且属于当前处理代次时，Assistant 输出才会被接受。不受支持的问题会弃答。论文文本是不可信输入，不能覆盖系统策略，也不能要求模型忽略证据验证。

系统不会存储或公开思维链。对于产品行为和评估而言，有界的答案文本、论断级引用、验证结果、提供商报告的令牌可用性/数量、延迟和安全失败类别已经足够。价格在请求路径之外计算；若提供商不返回令牌用量，则记录为 `unavailable`，绝不估算。

Assistant 证据反馈使用闭合的纠错词汇表，而不是通用赞踩或情感分数。只有在响应、线程、溯源信息、论文、主体和当前处理代次均匹配，且任何论断/证据块目标都能在持久化答案证据映射中找到后，`POST /v1/papers/{paper_id}/assistant/feedback` 路由才会接受幂等操作。可选的纠错详情属于私有数据，并从调试输出中脱敏；每个反馈响应都为 `private, no-store`。

## 私有产物

标注、备注正文、证据卡片、检查点、研究记忆项目和归账户所有的 Assistant 证据反馈默认均为私有。通用推荐输入、训练、日志、崩溃报告和不含内容的产品遥测都会排除这些数据。记忆复习与归档始终独立于 Library 状态。

已实现的账户导出/删除 API 和数据表清单如下：

- `GET /v1/annotations/export` 返回限定主体范围的 JSON 或 Markdown。小型导出保留单响应契约；`paged=true` 会切换为无损的有界序列，适用于单篇论文或完整账户。每个部分包含一项完整产物，以及解释或导入它所需的最少父级/引用上下文。其不透明的 `next_cursor` 经加密，并绑定主体、可选论文范围和导出快照；它同时出现在 JSON 页面元数据与响应标头中。`format=manifest` 仍是有界的按论文摘要。导出内容包括标注与选择器、保留的冲突、重新锚定尝试、证据卡片、检查点、记忆项目、绑定所有者的 Assistant 线程/消息、针对具体证据的 Assistant 反馈（包括可选私有纠错详情）、私有来源信息、规范 Library 元数据/私有收藏备注，以及引用元数据/原始链接。导出不会包含重建的论文全文或主体标识符。
- 当 Assistant v2 已启用而标注未启用时，同一个有界导出仍可从 `You -> Settings -> Account` 访问，确保私有 Assistant 历史、证据反馈和来源信息不会只因标注界面暗置就变得无法删除或访问。移动端操作会在请求前后重新检查账户范围，并且只在验证响应后才复制。当还有下一部分时，已确认提交的复制提示会显示 `Next part`；任何本身有效的备注都无需为了放入单个移动响应而缩短或删除。
- `POST /v1/annotations/import` 在幂等键与 8 MiB 请求上限之下，只接受上述 JSON 架构中带标注的子集。事务会验证保留的论文/处理代际/块文本和偏移量，恢复冲突及重新锚定历史，跳过等价 ID，并在 ID 冲突或来源不可用时中止整个导入。它绝不会导入 Library 状态、论文、证据卡片、记忆或 Assistant 历史。
- 单条标注、证据卡片和记忆的删除是幂等墓碑，并会清除私有正文。账户删除会级联清除 `research_artifact_sync_metadata`、`research_artifact_operations`、`annotations`、`annotation_conflicts`、`annotation_reanchor_attempts`、`annotation_imports`、`evidence_cards`、`reading_sessions`、`reading_checkpoints`、`memory_items`、绑定所有者的 `assistant_threads`/消息、`assistant_evidence_feedback_evaluations`、绑定所有者的来源信息，以及通过规范 `users` 所有权根关联的 Passport 反馈。共享论文元数据、共享规范化文档和共享派生产物会保留。
- Assistant 线程最初 30 天后过期，每次最多延长 30 天且不会超过创建后 90 天；每条线程最多保留 50 条消息，并以每小时最多 1,000 条的批次连同其私有来源信息一起移除。其他有效研究产物会一直保留，直到用户通过受支持界面删除它们或删除账户；检查点没有单独的删除路由。在另行审查的清除策略出现前，墓碑/冲突历史始终是同步/导出的一部分。

服务器流量受 TLS 保护，服务器存储依赖已部署基础设施中经过审查的静态保护措施。移动端 Drift 数据库并未由 Pakperk 在应用层加密：私有正文是普通 SQLite 文本，由操作系统应用沙箱、设备访问控制、平台文件保护和已配置处的备份排除来保护。在平台威胁模型和迁移/恢复设计获得批准前，SQLCipher 保持延期。不得把当前移动数据库描述为静态加密。

数据库级联和仓库测试证明了可执行机制；隐私/法律审查、签名设备清理、真实删除、隔离恢复和当前台账重新应用证据仍为 `not_ready`，并会阻止私有功能分阶段发布。

## 兼容 API

Plan 03 在 `/v1` 下增加带版本的文档、Passport、Assistant、标注、证据卡片、检查点、记忆、版本和差异界面。现有 Introduction 和 `/chat` 路由会在兼容窗口期间继续可用。生成的 [OpenAPI 契约](openapi-v1.json)对于当前构建中存在哪些操作具有权威性；绝不能用本产品技术契约替代生成的 API 证据。

当前契约还提供当前处理代际语义范围读取、Passport 反馈、针对具体证据的 Assistant 反馈，以及主体范围的标注冲突恢复。Assistant 反馈绑定到确切的主体/当前处理代际答案，并采用操作 ID 重放回执；不接受通用情感反馈。冲突分页有修订隔离且已密封；重新安装的客户端无需依赖旧的本地标注缓存，即可重建完整冲突队列。检查点读取接受确切的论文范围，因此当前论文不会被隐藏在账户级保留/页面边界之后。

当前 Passport worker 是确定性的溯源信息基线。它会把全部十个类型化字段发出为有来源支持的 `supported`、`not_found` 或 `not_applicable`，并提供逐字段溯源信息；这不表示任何模型质量。当前版本差异算法是 `stable-key-content-similarity-v2`：它使用稳定键、精确内容哈希和针对修改内容的有界相似度信号来比较元数据、块、章节、图、表、公式、Passport 字段和参考文献。它会标明解析器变更不确定性，但不会声称提供了经过验证的语义文本编辑评分。

发布较新的文档处理代际会将一项独立、有界的后台标注重新锚定任务加入队列。同一稳定块上或匹配引用上下文中的唯一精确引文可以自动移动；唯一达到高门槛的模糊候选会记录为 `uncertain`，没有匹配则变为 `orphaned`。后两种情况都不会在无提示的情况下提交为已锚定移动。用户可以手动将已有标注重新附加到同一论文中较新且保留的处理代际，但必须提供精确目标范围并匹配乐观修订。该操作会在同一私有、幂等历史中记录一次 `manual` 重新锚定尝试。在这些保守基线通过受保护的质量门禁前，它们始终暗置。

## 默认关闭的控制项

服务器和 Helm 契约提供以下开关，默认均为 false：

| 环境开关 | Helm 键 | 依赖项 |
| --- | --- | --- |
| `DEEP_READER_ENABLED` | `deepReader` | 无 |
| `PAPER_PASSPORT_ENABLED` | `paperPassport` | Deep Reader |
| `SEMANTIC_FACETS_ENABLED` | `semanticFacets` | Deep Reader |
| `VISUAL_OBJECTS_ENABLED` | `visualObjects` | Deep Reader |
| `ASSISTANT_V2_ENABLED` | `assistantV2` | Deep Reader |
| `ANNOTATIONS_ENABLED` | `annotations` | 账户与 Deep Reader |
| `RESEARCH_MEMORY_ENABLED` | `researchMemory` | 账户、Deep Reader 与标注 |
| `VERSION_DIFF_ENABLED` | `versionDiff` | Deep Reader |
| `DOCLING_EXPERIMENT_ENABLED` | `doclingExperiment` | Deep Reader |

仓库、移动端、Helm 和环境默认值都将每个 Plan 03 开关保持关闭。若没有不可变的 `releaseEvidence.deepReaderReleaseId`，生产环境会拒绝任何已启用的 Plan 03 开关。该 ID 必须指向由 `scripts/deep_reader_release_evidence.py` 验证的完整证据包；单凭摘要不能证明受保护的人工、预发布环境、遥测或签名设备工作已经执行。
