# 移动应用 App Privacy 与 Data Safety 审核

**已审核代码基线：**Pakperk 移动端 `0.2.0+2`
**问卷状态：**已准备发布候选版本的答案；尚未提交
**分类体系核对日期：**2026-07-31

本工作表将已发布的移动端代码和面向后端的功能映射到应用商店披露信息。提交前，发布负责人必须将本表与完全一致的已签名构建产物、已部署的 SDK/处理方以及当前的应用商店问卷逐项核对。Apple 会分别考察是否收集、是否与身份关联、用途和跟踪；Google 则要求披露应用及其捆绑 SDK 将数据收集到设备外部的所有情况。请参阅官方的 [Apple App Privacy 详情](https://developer.apple.com/app-store/app-privacy-details/)、[Apple 隐私清单指南](https://developer.apple.com/documentation/bundleresources/describing-data-use-in-privacy-manifests) 和 [Google Play Data Safety 指南](https://support.google.com/googleplay/android-developer/answer/10787469)。

## 移动端实际行为

- 访客阅读无需账号。
- 账户功能会发送由 OIDC 支持的用户标识符；个人资料可以保存公开用户名/显示名称。
- 可选的账户注册和恢复流程使用已验证电子邮箱，由已配置的身份提供商（IdP）保留。Pakperk 应用数据库不会将该邮箱复制到 Pakperk 个人资料中。
- To Read 保存账户与论文之间的关系。评论和举报详情属于用户生成内容；屏蔽和内容审核状态属于账户操作。
- 默认关闭的 Deep Reader 功能可在账户选择使用时，同步私有批注与笔记、保留的冲突版本、重新锚定历史、证据卡、位置/模式检查点、记忆提示/回答和复习状态，以及助手对话/来源信息。上述正文都不会用作推荐或遥测输入。
- 应用不含广告 SDK、广告标识符、联系人/位置/照片/音频权限、支付 SDK 或跨应用跟踪集成。
- 身份验证使用系统浏览器。令牌仅保存在内存或平台安全存储中，不会复制到分析系统、偏好设置或 Drift 中。
- 自定义 OTLP 导出器仅发送封闭词汇表中的产品交互、有上限的计数/时长、部署环境和已脱敏错误类别。它不发送稳定的账户/设备/会话标识符，也不发送原始异常、堆栈、URL、搜索文本、论文标识符、公开用户名、电子邮箱、评论、摘要、Introduction、提示、回答、令牌或 Authorization 请求头。
- 系统不会为了制造良好的无崩溃率而吞掉框架/平台/Zone 致命故障。委托的应用报告只接收已脱敏错误类别和空堆栈；实际未捕获的脱敏替代异常会保留 Apple/Google 操作系统的正常崩溃语义。因此，根据平台政策，平台诊断可能会包含原生进程崩溃记录；但该边界不会传递应用异常消息或 Dart 堆栈。发布前仍必须审核已签名构建产物的处理方以及商店表单。
- 仅当直接对端属于已配置的入口代理 CIDR 时，评论操作和公开论文预处理/聊天才会从转发链中解析请求来源地址。系统从右向左评估该链；链缺失、格式错误或不可信时，会回退到直接对端。应用立即从所选地址派生 HMAC-SHA-256 作用域，不记录或持久化原始地址，且仅在已配置的限流窗口到期前（最长 30 天）保留带密钥的假名标识。该标识仍属于需要披露的网络/安全标识符；它与不含标识符的移动端遥测彼此独立。
- 应用遥测 span 不包含对端地址、原始 URI、请求头或正文。但是，生产 API/遥测入口仍可能按其数据控制者的全局日志策略处理或保留源 IP 访问数据，因此已签名部署与处理方证据仍是发布阻断项。
- 生产和预发布环境使用 TLS。Android 备份已禁用。iOS 本地数据不会进入备份，且使用平台文件保护。Drift 数据库本身是普通的、应用层明文 SQLite 数据库，包括私有研究正文；它依赖操作系统应用沙箱、设备访问控制、文件保护和备份策略来获得保护。SQLCipher 尚未实现，需等待其威胁模型以及迁移/密钥恢复设计完成审核。不得在任何问卷中声称 Pakperk 在应用层加密了此本地数据库。

## Apple App Privacy 答案

请对生产环境所有已启用功能的并集采用保守披露：

| Apple 数据类型 | 关联 | 用途 | 原因 |
| --- | --- | --- | --- |
| 姓名 | 是 | 应用功能 | 可选的公开用户名/显示名称和个人资料 |
| 电子邮箱地址 | 是 | 应用功能 | 可选的账户注册、验证、登录和身份提供商（IdP）处的恢复；不会复制到 Pakperk 应用个人资料数据库 |
| 用户 ID | 是 | 应用功能 | OIDC/本地账户身份 |
| 其他数据类型 | 是 | 应用功能 | 为评论和高成本公开操作的共享滥用限流而保留的带密钥、可信请求来源作用域，以及经过审核的生产边缘网络/安全处理 |
| 其他用户内容 | 是 | 应用功能 | 评论和举报/支持自由文本；可选的私有批注、笔记、证据卡、记忆提示/回答和助手对话 |
| 产品交互 | 是 | 应用功能；分析 | 与账户关联的 To Read、检查点/记忆复习和研究构建产物操作，以及不含标识符的交互遥测；由于该类别也存在关联用途，因此关联标记为“是” |
| 崩溃数据 | 否 | 分析 | 自定义导出器仅接收已脱敏的 `timeout`、`format`、`state`、`argument` 或 `unexpected`；未捕获的“脱敏类别 + 空堆栈”替代异常可能按平台政策保留由操作系统管理的独立原生崩溃诊断 |
| 性能数据 | 否 | 分析 | 有上限的启动时长和缓存/交互性能信号 |

Apple 将 Device ID 定义为广告标识符或其他设备级标识符。保留的 HMAC 作用域是由同一网络来源后的每台设备共享的短期网络来源假名标识，因此 **Other Data Types** 是准确而保守的类别；选择 Device ID 会误导性地暗示该值是设备级标识符。Apple 关于 IP 的指南要求根据用途分类，且 App Functionality 用途明确包括防欺诈与安全。根据 Apple 的保留定义，为处理请求而弃置的原始请求地址本身不属于“收集”；此处披露则涵盖了已保留的带密钥作用域，以及生产边缘可能执行的安全/访问保留。请参阅 [Apple App Privacy 详情](https://developer.apple.com/app-store/app-privacy-details/) 和官方 [隐私清单数据类型值](https://developer.apple.com/documentation/bundleresources/app-privacy-configuration/nsprivacycollecteddatatypes/nsprivacycollecteddatatype)。

应用级 `PrivacyInfo.xcprivacy` 特意描述 App Store 隐私标签所代表的应用/后端数据收集，而不仅是 SDK 的直接收集。每个已捆绑的第三方 SDK 仍需自行负责其隐私清单；提交前必须检查已签名归档的隐私报告，确认合并后的并集。

对每一类数据选择 **Data Not Used to Track You**，并回答应用不会跟踪用户。不得选择广告、营销或个性化。`mobile/ios/Runner/PrivacyInfo.xcprivacy` 必须与本表以及已签名归档生成的合并隐私报告一致。如果依赖项新增了隐私清单或数据收集行为，必须在提交前重新评估整体并集。

## Google Play Data Safety 答案

建议的生产环境映射如下：

| Google 数据类型 | 收集/用途 | 必填/可选 |
| --- | --- | --- |
| 个人信息—姓名 | 为应用功能/账户管理而收集 | 可选；访客阅读无需此项 |
| 个人信息—电子邮箱地址 | 由身份提供商（IdP）为账户管理、验证、登录和恢复而收集 | 可选；访客阅读无需账户，且 Pakperk 应用个人资料数据库不会复制该邮箱 |
| 个人信息—用户 ID | 为应用功能/账户管理和安全而收集 | 可选；仅在选择账户功能时才必需 |
| 设备或其他 ID | 为防止滥用、确保安全和共享限流而收集带密钥的请求来源网络标识符；生产边缘也可能处理源 IP 访问数据 | 请求到达这些受保护的服务/边缘边界时自动执行；绝不用于广告或跟踪 |
| 应用活动—其他用户生成内容 | 为应用功能/安全而收集（评论、举报文本，以及可选的私有批注/笔记/证据/记忆/助手内容） | 可选 |
| 应用活动—应用交互/其他操作 | 为账户功能（To Read、屏蔽/举报、检查点、记忆复习和研究构建产物操作）以及分析（封闭词汇事件）而收集 | 功能为可选；生产分析启用后自动执行 |
| 应用信息与性能—崩溃日志 | 自定义导出器会收集已脱敏错误类别；未捕获的“类别 + 空堆栈”替代异常可能另行生成由操作系统管理的原生崩溃诊断 | 生产遥测已启用或平台诊断策略适用时自动执行；必须核验已签名部署和控制台设置 |
| 应用信息与性能—诊断 | 为分析而收集有上限的启动/缓存时序和结果数据 | 生产遥测已启用时自动执行 |

对“传输中加密”和“提供账户删除机制”都回答 **Yes**。应用不会出售数据，也不会将数据用于广告。只有在合同和已部署路由能够确定身份、托管、数据库、备份和遥测供应商仅根据适用的 Google 例外条款作为服务提供商行事后，才能回答“未共享”；否则必须披露该数据传输。除非已附上独立安全审核的最终报告，否则不得声称已完成该审核。

## 需要对齐的保留/删除声明

公开政策和应用内置政策必须保持同一时间表：

- 活跃个人资料/文献库/评论/屏蔽/举报/提供方身份：在账户活跃期间保留，随后由账户删除流程移除；提供方身份包含为注册和恢复而保留的已验证电子邮箱；
- 带密钥的请求来源滥用限制作用域：保留至已配置的限流窗口到期（最长 30 天），然后由有上限的维护任务删除；可恢复副本仍受下述备份期限约束；
- 阅读简报：35 天；应用内通知：30 天；参与事件的重试/幂等记录，以及已完成/失败的通知任务：30 天；每小时针对每张表的删除查询最多处理 1,000 行；
- 助手线程：初始保留 30 天，每次最多延长 30 天，且任何情况下都不超过创建后 90 天，每个线程最多包含 50 条消息；每小时清理最多删除 1,000 个过期线程及其私有来源信息；
- 批注/冲突/重新锚定历史、证据卡、检查点和记忆项：在支持单项删除的地方保留至单项删除，否则保留至账户删除；条目墓碑会清除正文，但不声称它们具有更短的例行清理周期；
- 账户作用域的移动研究数据行、冲突、缓存版本构建产物和待处理研究待同步队列（outbox）任务：由本地退出登录/账户切换和账户删除清理移除；仍等待完全一致的已签名设备证据；
- 可恢复的数据库/身份备份和 PITR 历史：最长 35 天；
- 已匿名的安全/内容审核审计：90 天；
- 不含内容的遥测和平台/应用日志：30 天；
- 已签名的删除授权记录：至少 400 天；如果需要更久，则保留至任何可恢复备份都无法恢复该账户，随后执行受控清理。

已签名的删除授权记录包含带密钥的指纹和已加密的提供方恢复坐标，不包含个人资料或评论内容。在重新应用删除授权记录之前，恢复操作必须在失败时默认拒绝。

## 受监控的支持联系方式金丝雀测试

在批准 `legalReviewId` 之前，必须对完全一致的已发布版本界面执行以下有界金丝雀测试：

1. 创建一个唯一、不敏感的金丝雀标签。不得包含凭据、账户标识符、用户生成内容或生产事故数据。
2. 通过已发布的 `/support/` 路径提交一次该标签，再通过向用户展示的已配置支持电子邮箱路由提交一次。在对某条路径的结果完成分类前，不得重试该路径。
3. 确认两封消息均已进入受监控队列，在已公布的支持服务目标时间内获得确认，且可以在不将消息正文暴露到发布证据的情况下与两次尝试建立关联。
4. 按正常的支持数据保留政策删除或关闭金丝雀记录。受保护清单中只保留 UTC 时间窗口、尝试/成功计数、路由/版本哈希、队列或工单引用哈希、清理结果和支持负责人批准。

路由缺失、接收超时或未收到、重复投递、清理失败或目标未受监控，都会阻止发布。仓库验证器可以检查封闭的结果结构，但无法创建实时投递或人工批准。
