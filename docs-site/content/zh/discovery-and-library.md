# Plan 02 发现与 Library 后端技术契约

**状态：** 后端技术契约已在默认关闭的标志之后实现。移动端开放和生产启用仍是相互独立的受保护分阶段发布门禁。

本文档记录迁移 12 至 18 所加入的当前源代码行为。控制性不变量仍是[已认证阅读信息流契约](reading-feed.md)：只有一份权威快照证明有效的 Inbox/Read next/Reading 集合为空后，已登录自动信息流才可以推荐。搜索、资料编辑、列表、标签、反馈、阅读简报、订阅和通知绝不会越过该门禁。

## 能力边界

| 能力 | 服务器开关 | 依赖项 | 权限边界 |
| --- | --- | --- | --- |
| 五状态 Library、列表、标签、备注、变更信息流 | `LIBRARY_V2_ENABLED` | 账户 + Library | 复用规范 Library 修订；有效状态的变更可能影响队列资格。列表/标签/备注则不能。 |
| 研究资料 | `RESEARCH_PROFILES_ENABLED` | 账户 | 只影响未来发现偏好；每个响应都声明 `queue_override=false`。 |
| 高级推荐模式、理由、说明和反馈 | `RECOMMENDATIONS_ENABLED` | 账户 + Library + 阅读信息流 | 高级批次绑定已证明为空的 Library 修订，以及当前资料/反馈修订。此开关关闭时，阅读信息流仍可持久化一个绑定权限的最小 Recent 回退批次。 |
| 可选交互事件 | `RECOMMENDATION_EVENTS_ENABLED` | 无 | 闭合且不含内容的评估输入；绝不成为产品权威状态或队列权威状态。 |
| 公开确定性 Lookup 与建议 | `SEARCH_LOOKUP_ENABLED` | 无 | 仅含元数据的明确导航，以及有界的本地主题词表建议。 |
| 公开 Explore | `SEARCH_EXPLORE_ENABLED` | Lookup | 有界的本地 arXiv 覆盖范围，并附带“非系统性检索”免责声明。 |
| 账户所有的已保存查询 | `SAVED_QUERIES_ENABLED` | 账户 + Explore | 只保存查询定义；收藏论文仍使用规范 Library/导入流程。 |
| 阅读简报 | `READING_BRIEFS_ENABLED` | 阅读信息流 | 队列有效时生成队列简报；只有权限已证明为空时才生成发现简报。专用简报进度绝不会改变或证明队列状态。 |
| 订阅 | `SUBSCRIPTIONS_ENABLED` | 账户 + Library + 阅读信息流 | 存储明确的主题/分类/作者/已保存查询意图；不能越过队列策略投递。 |
| 应用内通知 | `NOTIFICATIONS_ENABLED` | 订阅 | 发现内容的投递绑定修订，并在队列状态非空或未知时延后。推送和电子邮件仍不可用。 |

所有开关默认均为 false。若启用的子能力依赖项处于关闭状态，启动会被拒绝。`RECOMMENDATION_EVENTS_ENABLED` 特意保持独立，因为事件收集是可选能力；即使它不可用，产品状态也必须保持正确。当 `READING_FEED_ENABLED=true` 且 `RECOMMENDATIONS_ENABLED=false` 时，已证明为空的快照可以只持久化并提供一个绑定权限的最小 Recent 批次，从而让最终的空修订复查和阅读简报仍然安全。高级模式、由资料得出的理由、说明和反馈路由保持禁用；因此仅含 Recent 的项目会发出 `explanation_available=false`，配置的增强批次则发出 true。

移动端事件发送器只做尽力而为的发送，且数据仅保存在内存中。它按照闭合的 12 事件/五模式架构发送数据，每批最多 50 个；它采用 UUID 事件身份和 UTC 时间戳，并在账户或匿名范围改变时同步清除待处理工作。禁用个性化会移除账户行为事件；必要的账户收藏/移除/Library 状态信号可以保留。事件端点被禁用或发生故障绝不能阻塞 Library、队列或阅读器状态。账户行为事件还受服务器保存的偏好设置隔离，因此被修改的客户端也无法绕过退出选择。v0.1 服务器会以 `INTERACTION_CONSENT_REQUIRED` 拒绝每个匿名事件批次：匿名会话 UUID 只是请求范围，不是可验证的同意；访客既没有分析同意控件，也没有账户 Library 状态。

## 账户私有界面

除非代码优先 OpenAPI 另有说明，以下所有路由都要求 bearer 认证，并返回私有、禁止存储且按授权变化的响应：

- `/v1/library/...` 提供五状态项目、列表、标签和一个统一的带修订变更流。写入具有幂等性，绝不会把 PDF 工作加入队列。
- `/v1/discovery/profile`、`/interests`、`/topics/{topic_id}`、`/authors/{author_key}`、`/reset` 和 `/export` 提供受修订隔离的偏好设置，并将明确数据、反馈数据和推断数据分组展示。
- `/v1/discovery/batches/{batch_id}/papers/{paper_id}/explanation` 和 `/feedback` 只接受归当前账户所有、尚未过期且由服务器创建的批次/项目组合。
- `GET/POST /v1/search/saved` 用于列出或存储明确的查询定义。`DELETE /v1/search/saved/{saved_search_id}` 以可重复安全的方式只移除调用者自己的定义。对于存在且归其所有的行、已不存在的行，或属于该账户范围之外的 ID，它都会返回 `204`，从而绝不泄露所有权。同一事务会停用关联的已保存查询订阅、清除其显示标签、停止已排队的评估，并让待处理匹配/摘要通知过期。删除操作不是清除查询历史，也不会收藏、移除或准备任何论文。
- `/v1/me/reading-briefs` 的创建/当前端点和 `/v1/me/reading-briefs/{brief_id}/progress` 是唯一的阅读简报权限来源。阅读信息流请求可以传入归该账户所有的 `brief_id`，并取得可空且只读的 `{id,position,total,complete}` 摘要，但前提是简报的确切 Library 修订和队列/推荐权限与返回页面相符。信息流不能创建、选择或更新简报，简报进度/完成状态既不改变也不证明队列为空。创建操作使用已存储的 `brief_size`（15–25，默认/回退为 20）；未明确提供模式时使用已存储的 `preferred_discovery_mode`，资料查询失败则回退为 Recent。明确请求的模式优先。`/v1/subscriptions`、`/v1/notifications` 和 `/v1/notification-preferences` 也始终从属于阅读信息流权限。

公开的 `GET /v1/search/lookup`、`GET /v1/search/suggestions` 和 `POST /v1/search/explore` 只搜索有界的本地元数据。建议是由最多八条 `{topic_id, label, source_vocabulary}` 记录组成的确定性列表；它们不会进行外部查询，也不会改变队列。打开结果属于明确导航。要添加论文，请使用规范的[手动导入契约](paper-import.md)或 Library 写入；在兼容客户端中，待处理收藏会立即抑制推荐。这些公开搜索响应仍采用 `Cache-Control: private, no-store` 和 `Vary: Authorization`；未保存的查询不会成为服务器端历史。

Lookup 排名具有确定性，依次考虑：完全匹配的规范化 arXiv 身份、完全匹配的 DOI、完全匹配的标题、高标题三元组相似度、确切作者加匹配的标题词元，最后是相关全文；发布时间较新和稳定论文 ID 用于打破平局。Explore 采用可审计、固定权重的本地融合：直接文本为 `1.0`，已发布引用邻居边为 `0.25`，明确主题/分类筛选为 `0.125`。摘要向量检索是可选的；在配置兼容的查询嵌入模型前始终不可用，服务绝不会用虚构的向量分数代替它。每个响应都会保留闭合集合的来源诊断，以及有界/非系统性覆盖范围免责声明。

## 用户选择的 Library 提醒

有效的 Inbox、Read next 或 Reading 项目可以带有一个账户私有的 UTC `reminder_at`。Library v2 写入采用补丁语义：省略字段会保留原值；JSON `null` 会清除该值；未来时间戳会设置或替换该值。Reviewed、Archived、已移除或已过期的值会被服务器拒绝。将项目移出有效队列或移除项目会清除提醒。导入成功后的操作会立即打开同一个账户范围的 Library 编辑器；快捷收藏仍保持静默。

`user_selected_reminder` 是闭合的应用内通知类型，拥有自己的 `immediate|daily|weekly|off` 偏好设置，默认值为 `immediate`。其 worker 会锁定账户，应用全局暂停、免打扰时段、应用内启用状态、每日预算及按类型频率，并只创建归队列所有的论文通知。幂等性边界是账户 + 论文 + 精确到微秒的提醒时间戳。载荷只包含提醒纪元；绝不会复制标题、备注、列表、标签、查询或账户标识符。清除、替换、使 Library 项目失效或移除项目，都会让旧的未读通知在列表查询时失去资格。关闭通知只会改变通知状态，绝不会改变或推进 Library 队列的权威状态。

通知部署标志独立控制提醒工作的创建和执行。回滚期间，已排队或租约过期的提醒工作会安全结束且不进行评估，其他互动工作会继续。移动端会让已有提醒保持可见且可清除，但禁用新提醒选择，并使用中性的“整理论文”导入操作。重新启用不会复活任意久远的承诺：调度与评估共用严格的 24 小时逾期投递窗口。早于该窗口的时间戳会保持可见，直到用户清除它或再次明确收藏该项目；编辑器随后会说明已完成的提醒将被清除。分阶段发布证据必须演练这种休眠工作和禁止延迟投递的行为。

## 来源条款与署名

Lookup、Explore、建议、推荐卡片和阅读简报使用仓库的规范 arXiv 元数据边界。保留论文作者、标题、带版本的 arXiv 身份和规范摘要页链接；不得暗示论文归 Pakperk 所有。Pakperk 与 arXiv 不存在关联，也未获得 arXiv 背书。Explore 必须显示其有界本地来源诊断和“非系统性检索”免责声明。主题建议会保留 `source_vocabulary`，因此产品标签不能被描述为推断得到的用户关注项或通用分类法。

现有的[全文与 arXiv 数据策略](content-policy.md)仍然管辖元数据、链接、PDF 和派生内容。仓库测试固件或成功搜索并不能完成发布审查：生产使用前，必须在候选版本证据中附上确切启用的来源、署名呈现方式、使用条款、配额，以及有资质的内容/法律批准。

## 反馈的真实性

接受反馈会推进 `recommendation_feedback_revisions`。批次构建、持久化和提供服务会绑定该修订、可选资料修订和已证明为空的 Library 修订。若不匹配，尚未提供服务的批次会被取代。每个包含推荐 `batch_id` 的响应还会携带确切的 `batch_metadata` 元组：资料修订、反馈修订、算法版本和推荐策略版本。仅当批次 ID 不存在时该元组才不存在，而且它是移动缓存有效性的一部分。批次的范围限定为对应的已授权游标页面：响应可以同时携带 `batch_id` 和 `next_cursor`，而续页可以使用不同的批次 ID。兼容客户端只有在强制规则、队列决策/Library 修订、生效模式和不可变元数据元组都相同时，才会追加页面。客户端会保留每个项目的来源批次和从零开始的页内重排位置，用于绑定批次的操作与事件；它绝不会把包含不同批次的合并遍历缓存到同一个批次身份下。生成通过归账户所有的独立任务队列运行。worker 会认领有界任务，基于任务所绑定的 Library/资料/反馈权限构建，并在发布前重新检查这些隔离线；它不能削弱同步阅读信息流对空队列的证明。每页的续页坐标和候选行会被持久化，因此分页绝不会提供未绑定的结果集。同一快照中的候选读取会排除反馈中保留的每个确切/基础 arXiv 身份；不相关和已关闭项目是硬排除项。符合条件的曝光只会增加一个有上限的重复惩罚。

只有已经开启个性化时，相关反馈才会创建 `source=feedback` 的主分类亲和度。For You 可以使用另行标注的反馈或推断亲和度，并且必须说明实际来源。Following 只使用明确兴趣。Reset All 会删除原始反馈、反馈修订、交互、批次和非明确资料兴趣。资料兴趣/导出界面显示分离的聚合结果，而不是原始的按时间排列反馈历史。

说明代码和候选来源是闭合的线协议枚举。其中包括 `saved_query_match`，其来源为 `saved_query`；已保存查询理由会报告真实存储的定义，绝不会暗示用户明确关注了某个主题或作者。

## 隐私与保留

- 明确的资料/Library/已保存查询/订阅数据会保留到相应的重置、项目删除或账户删除。删除已保存查询会硬删除其规范化定义和有界收藏重试绑定；清除其原始显示标签后，只保留不含内容的订阅审计身份/修订数据。
- 研究资料重试绑定 30 天后过期；已保存搜索重试绑定使用服务器分配的有界到期时间。
- 推荐批次和候选项当前 24 小时后过期。不含内容的交互事件 90 天后过期，原始推荐反馈 180 天后过期。超过 30 天的终态/休眠/租约过期推荐生成任务由有界维护清除。
- 阅读简报 35 天后过期。应用内通知、互动重试/幂等行以及已完成/失败的通知工作 30 天后过期。每小时维护中，每张表每轮最多删除 1,000 行。
- 未保存的 Lookup/建议/Explore 和已提交导入文本不会存储为服务器查询历史。搜索日志和遥测绝不能包含原始查询、标题、URL、账户、论文、游标、令牌、私有备注、理由详情或通知载荷。
- 账户删除会级联清除所有归账户所有的 Plan 02 行。公开论文和规范主题元数据会保留，因为它们不归账户所有。

有关运营策略和受保护证据要求，请参阅[隐私声明](legal/privacy.md)、[可观测性运行手册](runbooks/observability.md)和[账户删除运行手册](runbooks/account-deletion.md)。

## 分阶段发布与回滚

迁移 12–18 是在已部署架构 11 上执行的加法迁移。请从经过验证的隔离恢复环境中演练确切的 11 到 18 路径，在功能回滚期间保留架构 18，并在执行一次架构兼容的旧代码演练后再次向前迁移。不要使用向下迁移关闭能力。

迁移 12 是扩展迁移，不是物理上的 To Read 到 Inbox 收缩迁移。当 v0.0 代码可与架构 18 共存或回滚到该架构时，逻辑 Inbox 仍存储为 `to_read`；v2 代码会把这个别名解码为 Inbox，并把 Inbox 编码回 `to_read`。旧版操作指纹对 v0 重放保持不变，而可空的 v2 指纹会携带新写入的完整私有备注/来源/提醒意图。旧版 Library 列表会把 Inbox、Read next 和 Reading 投影为其单一 `to_read` 集合；v2 的 `state=inbox` 筛选仍保持完全一致。

在写入任何 Read next 或 Reading 值之前，可以使用经过验证的 v0.0 镜像对架构 18 执行回滚。启用 Library v2 写入后，回滚目标必须是理解全部五种逻辑状态的最后一个扩展兼容镜像；此时 v0.0 不再是安全的代码回滚目标。无论哪种情况，都要保留架构 18 并关闭功能开关。

应按依赖关系和风险依次启用：Library v2；研究资料；Lookup，然后是 Explore 和已保存查询；影子评估中的推荐/事件存储；只有通过队列/隐私/评估门禁后才启用阅读信息流推荐模式；接着是阅读简报、订阅，最后是通知。强制已认证的队列优先界面仍是最终客户端采用门禁。回滚按相反依赖顺序进行，同时保留普通公开信息流、现有 Library 读取、账户删除和架构 18。

在 For You 或发现内容投递离开影子阶段前，需要绑定离线评估语料库和结果摘要、生成器/功能/评分/多样性策略版本、来源覆盖和主题/作者集中度结果、值为零的队列泄漏目标，以及负有责任的研究/产品/隐私审查。并发属性测试必须覆盖收藏/移除/账户切换/修订竞态；失败时拒绝测试必须覆盖数据库、认证和来源不可用；保留与账户删除测试必须覆盖每一个归账户所有的数据类别。这些仓库检查是先决条件，不是真实候选版本证据。

已纳入版本控制的仓库离线门禁包括一个可执行的 18 用例队列策略矩阵和带版本的推荐测试固件，覆盖明确资料、预期候选池、稀疏分类、误导性标题重叠、模糊作者姓名、arXiv 版本重复、非有效历史种子理由、负面反馈和小幅资料变更。它会测量 Recall@K、nDCG@K、目录/主题和冷启动覆盖率、多样性、新颖性、作者/分类集中度、说明正确性、负面反馈响应和排名稳定性。它还会报告使用明确单位的确定性延迟微秒、微美元成本、生成器调用次数、生成器文档工作单元和外部请求预算。这些资源门禁不能替代人工相关性判断、生产延迟/成本、在线指标、经过批准的 A/B 分组和停止策略，也不能替代受保护的生产观测门禁。

仓库测试和渲染后的标志只是机制证据。生产环境要求确切的 11 到 18 恢复/迁移/回滚结果、完整功能映射依赖演练、真实隐私扫描、保留清理观测、队列不变量和告警金丝雀、签名客户端验收，以及负有责任的数据库/服务/平台/隐私/移动端/发布批准。
